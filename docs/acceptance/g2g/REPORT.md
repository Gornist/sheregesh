# Задержка видео «стекло–стекло»: HDMI-источник devbox → пульт (первый замер)

**Дата:** 2026-10-30 · **Образ плат:** `40d1e09` · **Средство:** `tools/probe/g2g_latency.py` ·
**Источник:** `tools/lab-video/hdmi_testpattern.py` на GTX 1650 devbox (`hdmi_source.sh start`).

Путь: отрисовка кадра GTK на devbox → композитор GNOME и вывод HDMI → конвертер MS2130 → захват UVC (YUYV
1280×720@30) и аппаратный H.264 на pi2 → SRTP → декодер pi1. Время из кадра — штрихкод (32 бита мс от полуночи UTC,
часы devbox); момент получения — часы pi1 при выдаче декодированного кадра (тот же сокет, что у GUI). Смещение часов
измерено напрямую (UDP, 50 проб, наименьший RTT), не по NTP.

| Показатель | Значение |
|---|---|
| Кадры | 900 прочитано, 0 нечитаемых за 30 с (30 к/с) |
| Задержка | min 144 · **p50 151** · p95 155 · max 165 · среднее 151,1 мс |
| Смещение часов devbox − pi1 | −50,6 мс (RTT 0,59 мс, погрешность ≤ 0,3 мс) |

Для сравнения — в том же прогоне ранее: захват на pi2 → декодирование на pi1 (`check_video_link` latency) p50 61 мс.
Около 90 мс приходится на сторону источника до метки захвата pi2: композитор и vsync devbox (до 1–2 кадров 60 Гц),
преобразование и буфер MS2130, очередь буферов UVC (захват 30 к/с при сигнале 60 Гц). Разбивка — гипотеза, не замер.

**Не входит:** показ на дисплее пульта (у pi1 нет дисплея) — добавит вывод GUI и развёртку панели.
**Замечание:** часы devbox по NTP отличались от pi1 на 50 мс — по NTP замер ошибся бы на треть.
