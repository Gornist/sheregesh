на SD, что рабочее хранилище; код хранилища — из образа платы):

| Случай | pi1 | pi2 |
|---|---|---|
| сбой на каждой из 25 изменяющих операций `apply`, чистая остановка | 24 — прежняя ревизия, 1 — новая подтверждённая, смешанных 0 | то же |

| предыдущая ревизия до активации новой | во время проверки служб новой ревизии прежняя — подтверждённая, целостна, в снимках | то же |

Критерий «20 отключений питания в момент применения» не выполнен. Замену — 20 сбросов pi2 (`sysrq b`, без
синхронизации) во время непрерывного `apply` (`cfg_atomic.py loop` / `check`) — классификатор автономного режима
отклонил как вмешательство в работу стенда. Сброс без синхронизации — тоже не обесточивание: кэш SD-карты при нём
не теряется. TEST-CFG-002 — не PASS.

## 3. TEST-SYS-004 — работа без внешнего интернета

**L3 — свежий образ без сети (новый сценарий `boot_check.sh offline`, этап boot shbuild).** Образ `142c603`, QEMU
virt. DHCP без router и dns, весь трафик моста — tcpdump:

| Проверка | offline | положительный контроль (DHCP даёт DNS 9.9.9.9) |
|---|---|---|
| загрузка, упавшие юниты (кроме аппаратных) | running, 0 | — |
| маршрут по умолчанию / серверы DNS | нет / нет | 172.30.77.1 / 9.9.9.9 — FAIL |
| пакеты за пределы подсети стенда | 0 из 39 | 28 — FAIL |
| запросы DNS | 0 | 28 (`2.debian.pool.ntp.org`) — FAIL |
| записи err в журнале без сети | 0 | — |

В записях err остаются только запуск консоли без дисплея (аппаратный, `ALLOW_FAILED`) и правило `90-alsa-restore.rules`
пакета alsa-utils (GOTO без метки, то же на плате). Обычный сценарий `fresh`, где DHCP даёт маршрут, но не DNS, тоже
не отправил ни одного пакета наружу: без DNS chrony не находит пул.

Сценарий включён в этап boot shbuild (`BOOT_SCENARIOS`): задание `20261101-214646-d2cc53b` — PASSED, boot 410 с
(четыре сценария), offline — PASS. Первая попытка `20261101-211332-6d0ce10` упала на gates: `owners_check` не получил
loop-устройство на devbox, разовая гонка. Повтор того же кода прошёл.

**Стенд — обе платы без маршрута по умолчанию и DNS (`tools/probe/offline_stand.py`, 10 мин):**

|---|---|

Положительный контроль записи на pi1: `ping 9.9.9.9` — внешних 2, `getent hosts example.org` — запрос DNS 1.

Найдено в пробе и исправлено: `resolvectl dns eth0 ''` остаётся до `resolvectl revert`, `networkctl reconfigure` его
не снимает. После прогона DNS на обеих платах вернули вручную (`revert` + `renew`, имена снова разрешаются). Проба
теперь делает `revert` и проверяет, что DNS вернулся.

Не выполнено: первая загрузка свежезаписанной карты на стенде (запись карты — владелец) и запуск GUI с изменением
настройки в первой загрузке без сети. TEST-SYS-004 — не PASS.

## CI

С 2026-10-31 CI на `v2` падал в 11 тестах. Тесты проб вызывали `main()` без `--console`/`--remote`, и
`tools/stand/boards.py` искал платы в сети: в CI — «плата не найдена», а на машине со стендом юнит-тест ходил на
настоящую плату по SSH. Исправлено автофикстурой в `tests/conftest.py`: «auto» превращается в имя платы без сети,
кроме `tests/tools`, где поиск проверяется намеренно. Ещё два исправления:

- сервер RTSP: `stop()` сам снимает учёт генераторов (гонка с потоком `_stream`);
- клиент OTA: на Linux после ответа агента чтение даёт ECONNRESET вместо EOF — это конец потока; тест из `4ddbcb9`
  проходил только на macOS.
