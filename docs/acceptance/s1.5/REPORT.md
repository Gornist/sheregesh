## Найденные и устранённые ошибки (кроме визуальных)

1. CI `fa0206e`: в CI не находился `pyside6-lrelease` — инструменты Qt ищутся рядом с интерпретатором.
2. Агент слал heartbeat не чаще шага 0,2 с — шаг подстраивается под интервал.
3. После отказа по версии причина «major» затиралась на «closed».
4. При старте пульт поднимал «Нет связи» до первой попытки соединения — состояние «соединение» на время первого таймаута.
5. Видеогенератор переживал аварийно завершённый процесс блока — `setpriv --pdeathsig`.
6. `rtpjpegpay` требует I420; заглушка `libopenh264` в Ubuntu не кодирует — выбор кодека пробным кодированием.
7. `QTest.qWait`/`qtbot.waitUntil` держат GIL — видеотесты видели устаревшие кадры; ожидание через `QEventLoop` (`sheregesh_console.qtwait`).
8. Бэкенд на каждом такте перечитывал и хешировал файлы ревизии конфигурации — кеш активной ревизии.
9. Ctrl+C давал `KeyboardInterrupt` в слоте Qt, приложение не завершалось, лаунчер оставлял процесс блока — штатная обработка SIGINT/SIGTERM.
10. CI `de78758`: тест лаунчера брал системный `python3` без зависимостей — `SHEREGESH_PYTHON`.
11. Журнал пересылался в QML на каждом такте — отдельный сигнал при новых записях.
12. **60-минутный прогон:** свойства-списки `backend.events`/`backend.logs` в QML 6 — ссылки; фильтрация `.filter()` перечитывала и конвертировала весь список из Python на каждый элемент (O(n²), такт 7,5 с при 450 событиях). Фильтр и порядок перенесены в слоты `eventRows`/`logRows`; регрессионный тест — такт < 0,5 с при заполненных журналах (500/2000).
13. Страница «О системе» на каждое чтение запускала `gst-launch-1.0 --version` и пробное кодирование — значения вычисляются один раз.

## Что проверено и что нет

- **Проверено (L2/L3, x86, эмуляторы):** 26 TEST-ID с автотестами — отчёт `reqgen.py evidence`. Для всех Must вывод: «нужен L4: статус остаётся NOT TESTED».
- **Не проверено:**
  - Raspberry Pi 4, дисплей Waveshare, реальный Ethernet между двумя платами;
  - аппаратное декодирование H.264;
  - питание, тепловой режим, корпуса;
  - обновления A/B и подпись;
  - команды управления удалённым блоком — в S1.5 не реализованы, их нет в протоколе.

## Ограничения S1.5

- Видео в этой среде идёт в MJPEG, H.264 (openh264) — заглушка. Путь Pi 4 (`v4l2h264*`) — проба S2-4.
- Канал без аутентификации — допустимо только на изолированном стенде (ADR-0007).
- Снимки сняты программным рендерером без дисплея; на реальном HDMI-дисплее не проверялись.
