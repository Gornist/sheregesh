# Регламент проб S2 на Raspberry Pi 4

Пробы подтверждают или опровергают архитектурные решения TL-002: ADR-0002, ADR-0003, ADR-0006. Их результат — протокол пробы (PRE-CAD M-B01), а не смена статуса требования. Статус Must меняется только по испытаниям L4 из TEST-SPEC.

Инструмент — `tools/probe/s2probe.py`. Он использует только стандартную библиотеку, PySide6 нужен лишь пробе `gui`. Каждая проба пишет `<каталог>/<проба>.json` с исходными данными, критерием, вердиктом, коммитом и платформой. Пробы ничего не меняют в настройках ОС.

Результаты складываются в `docs/acceptance/s2/pi4/<дата>/`. Туда же кладётся `env.json` каждой платы.

## Условия проведения

- Две платы Raspberry Pi 4B и дисплей Waveshare по BOM v0.4; штатные блоки питания; температура помещения фиксируется в протоколе.
- Перед каждой пробой и после неё снимается `vcgencmd get_throttled` (входит в `env.json`). Проба при ненулевом флаге троттлинга или недонапряжения повторяется.
- Связь между платами — только прямой кабель на изолированном стенде: пульт 192.168.77.1/24, блок 192.168.77.2/24, без шлюза и DNS (ADR-0007). Канал без аутентификации. Подключать стенд к другим сетям нельзя.
- Видео — только синтетический `videotestsrc`.

## Что известно заранее

- **Выбор кодека.** `software/sheregesh/video.py` предпочитает `v4l2h264enc → v4l2h264dec`, проверяя каждую пару пробным кодированием и декодированием. При неудаче выбор откатывается на openh264/libav, затем на MJPEG. Фактическая пара видна на странице «О системе» и в `env.json` (`h264_pair`). Параметры аппаратного кодера (`extra-controls`, уровень 4 в caps) на Pi 4 ещё не проверялись — это первая задача S2-4а.
- **Вывод видео.** Сейчас кадры передаются из отдельного процесса декодера в GUI как RGBx 640×360. Путь `qml6glsink` из ADR-0003 не реализован. Если S2-4б не пройдёт по CPU, следующий шаг — `qml6glsink` или `appsink → QVideoSink` (ADR-0003, запасной путь).
- **CPU.** Загрузка измеряется по `/proc/stat` для всей системы. Вне Linux проба `gui` выносит FAIL: без замера CPU вердикт не выносится в пользу PASS.
- **Плато памяти.** Для сравнения с ARM — 3-часовой прогон на macOS arm64 в `REPORT.md`.
