# Регламент проб S2 на Raspberry Pi 4

Пробы подтверждают или опровергают архитектурные решения TL-002: ADR-0002, ADR-0003, ADR-0006. Их результат — протокол пробы (PRE-CAD M-B01), а не смена статуса требования. Статус Must меняется только по испытаниям L4 из TEST-SPEC.

Инструменты входят в пакет `sheregesh` и есть в образе: `sheregesh-probe` (`tools/probe/s2probe.py`) и `sheregesh-soak` (`tools/dev/soak.py`). Каждая проба пишет `<каталог>/<проба>.json` с исходными данными, критерием, вердиктом и платформой; настроек ОС пробы не меняют.

Результаты: `docs/acceptance/s2/pi4/<дата>/<плата>/` (копируются с платы `scp`).

## Чек-лист первого запуска (после получения штатного блока питания)

1. **Питание.** Штатный блок 5,1 В / 3 А USB-C. После загрузки `vcgencmd get_throttled` должен дать `0x0`, иначе результаты производительности недействительны.
2. **Образ.** Записать `sheregesh-lab-dev-pi4.img.zst` на карту: `zstd -dc … | sudo dd of=/dev/… bs=4M conv=fsync` или Raspberry Pi Imager → «Use custom». Строгий вариант `sheregesh-lab-pi4` — только для стенда без SSH (адрес 192.168.77.1).
3. **Первая загрузка.** Кабель Ethernet в локальную сеть (DHCP), дисплей и клавиатура — по возможности. Ждать 2–3 минуты: генерация хост-ключей SSH, первичная инициализация раздела данных.
4. **Вход.** `ssh sheregesh-ui@<адрес>` по ключу, переданному при сборке. Пароля нет, root заблокирован, sudo нет. Проверить `cat /etc/sheregesh/DEV-MODE`.
5. **Состояние.** `systemctl is-active sheregesh-remote-emu sheregesh-console seatd`, `journalctl -b -u 'sheregesh-*' --no-pager | tail` (пользователь в группе `adm`).
6. **Пробы с одной платой** (таблица ниже): `sheregesh-probe env --out ~/probe`, `sheregesh-probe h264 --out ~/probe`, `sheregesh-probe boot --out ~/probe --mark /run/sheregesh-ui/first-frame.json`.
7. **Сохранить** `~/probe/*.json` в `docs/acceptance/s2/pi4/<дата>/<плата>/` и записать в протокол: плату, блок питания, дисплей, температуру помещения.
8. **Откат к исходной системе платы** — перезаписать карту прежним образом (сохранить его заранее: `sudo dd if=/dev/… | zstd > backup.img.zst`).

## Разделение по условиям

| Условия | Проверки |
|---|---|
| **Одна плата и лабораторные эмуляторы** (без дисплея) | `env`; S2-4а; полный стек offscreen и `sheregesh-soak` (длительный прогон на ARM, TEST-SW-001 уровня L3); загрузка образа S2-1 и состояние служб по SSH; память и паузы на ARM |
| **Утверждённый дисплей** (Waveshare по BOM) | S2-3 (под cage, касание); S2-4б (окно 1920×1200); S2-2 до первого кадра на штатном дисплее; гашение экрана (UI-005, проба H1) |
| **Два физических устройства** | `sheregesh-probe link` (прямой кабель, 192.168.77.0/24); обмен SHRG-LAB между платами. **Блокировано:** канал работает только через loopback (ADR-0007, S1.5). До любых изменений — решение по аутентификации канала и отдельный изолированный стенд. Сетевой доступ эмулятора за пределы loopback не расширяется |
| **Специальные условия или оборудование** | штатный блок питания — для всех замеров производительности; S2-5 — управляемое отключение питания (реле или ручной цикл ×20 на каждом этапе); тепловой режим и климат — по внутренним методикам (D2); IP54 — H3 |

## Результаты 2026-10-23 на имеющихся платах (без штатного питания)

Две платы Raspberry Pi 4B Rev 1.5, 4 ГБ: исходная система владельца Debian 13 trixie, ядро 6.18.50+rpt-rpi-v8, Python 3.13.5, `throttled=0x0`, дисплея нет. Пакет `sheregesh` установлен через `apt` поверх исходной системы, службы не включались. Это не образ S2-1, а та же версия ОС и те же пакеты.

- `env`: PySide6 6.8.2.1, GStreamer 1.26.2, `v4l2h264enc`/`v4l2h264dec` есть, `qml6glsink` нет, `/dev/video10…31`.
- S2-4а: PASS (выше).
- Полный стек offscreen 90 с на pi1 (`soak-90-smoke.json`): два процесса, видео H.264 v4l2, все неисправности цикла отработаны, худшая пауза 162 мс, RSS пульта 144–148 МБ, сирот нет, восстановление есть. Функциональная проверка, не длительный прогон.
- Найдено и исправлено: `h264parse` (в Debian — `gstreamer1.0-plugins-bad`) отсутствовал в зависимостях, без него аппаратная связка не выбиралась; `soak.py` импортировал неиспользуемый `PySide6.QtTest`.

## Что известно заранее

- **Выбор кодека.** `video.py` предпочитает `v4l2h264enc → v4l2h264dec`, проверяя пару пробным кодированием и декодированием; иначе — openh264/libav, затем MJPEG. Фактическая пара — на странице «О системе» и в `env.json` (`h264_pair`).
- **Вывод видео.** Кадры передаются из процесса декодера в GUI как RGBx 640×360; `qml6glsink` из ADR-0003 не реализован и в trixie недоступен (элемента нет). Если S2-4б не пройдёт по CPU — `appsink → QVideoSink` (запасной путь ADR-0003).
- **CPU** измеряется по `/proc/stat` для всей системы; без замера вердикт — FAIL.
- **Права dev-пользователя.** `sheregesh-ui` не имеет root и sudo; polkit разрешает только запуск и остановку двух служб «Шерегеша» и перезагрузку (в том числе tryboot).
