# Этап S2 — промежуточный отчёт: проверка окружения без Raspberry Pi

**Дата:** 2026-10-23 · **База:** `e2ecc8e` · **Уровень доказательств:** L2/L3 (macOS arm64, эмуляторы)

Отчёт не меняет статусы реестра: все Must остаются `NOT TESTED`, гейт REQ-REL-001 — NO-GO. Пробы S2-1…S2-5 на Pi 4 не выполнялись — оборудования в этой сессии нет.

## Окружение

Рабочая станция разработчика, а не эталонная платформа: macOS 26.6 на Apple M1, Python 3.13.0, PySide6 6.12.0, GStreamer 1.28.8 (Homebrew). Пакета util-linux (`setpriv`) в macOS нет. Подробности — в `environment.txt`.

Отличия от эталона (Ubuntu в CI, Debian на Pi 4): GStreamer 1.28 вместо 1.24; нет `setpriv` и `prctl`; кодек — MJPEG, как и в CI.

## Результаты

**Автотесты.** До исправлений на macOS: 199 пройдено, 2 упало, 3 пропущено (нет GStreamer) — всего 204, совпадает с S1.5. После установки GStreamer упали ещё 2 теста, найдена ошибка 1 (ниже). После исправлений: локально 209 из 209, пропусков нет, процессов-сирот после прогона нет. В CI на `3340c2e` — 209 passed, https://github.com/Gornist/sheregesh/actions/runs/39947686843.

**Визуальная проверка на реальном дисплее** (`screenshots-metal/`, `renderer.log`). Кадры сняты в реальном окне на Retina-дисплее через аппаратный рендерер Qt RHI Metal (Apple M1, масштаб 2,0). В S1.5 использовался только программный рендерер без дисплея. Сбоев отрисовки, ошибок QML и расхождений с программным рендерером не найдено: темы, масштаб 125 %, RU/EN, потеря связи, активные события.

Захват экрана системными средствами недоступен (нет разрешения на запись экрана), поэтому кадры сняты самим приложением: `grabWindow` в режиме `--screenshots`, `QT_QPA_PLATFORM=cocoa`, `QT_QUICK_BACKEND=rhi`.

Это не проверка L4. Дисплей Waveshare, GPU VideoCore VI и OpenGL ES на Pi 4 — по-прежнему проба S2-1.

**Демо двух процессов** (`tools/dev/sheregesh-emu --demo`) на реальном дисплее: блок, видеогенератор, декодер и пульт запустились, рукопожатие `proto=1.0 -> ok`. Ctrl+C (SIGINT группе) завершает всё без сирот.

## Найденные и устранённые ошибки

1. **Видеогенератор переживал аварийно завершённый блок вне Linux.** Это повтор дефекта 5 S1.5 на macOS: нет `setpriv --pdeathsig` и `prctl`, а запасной путь `die_with_parent` работает только в Linux. Добавлен сторож `software/sheregesh/pdeath.py`: он следит за родителем и при его смерти отправляет SIGKILL команде. Сторож — только стандартная библиотека, запускается по пути с `-I`. Путь Linux не изменён. Тест сирот теперь проверяет и внуков, модульные тесты сторожа выполняются в CI (`b3467a0`).
2. **Тест лаунчера на macOS:** `ps` выводит полный путь `…/MacOS/Python`. Имя процесса теперь сравнивается без пути (`b3467a0`).
3. **Длительный прогон без GStreamer** требовал видео. Теперь видео проверяется только при наличии кодека, как в остальных видеотестах (`b3467a0`).
4. **Косметический дефект S1.5:** «с» в плитке связи при 150 % переносилась на отдельную строку. Во всех строках QML и в переводе между числом и единицей стоит неразрывный пробел, добавлен регрессионный тест (`5f77c7b`). Проверено снимком 150 % RU.

## Не выполнено (требует оборудования или решения владельца)

- S2-1…S2-5 на Pi 4: GUI на Waveshare, аппаратный H.264 (`v4l2h264enc/dec`) и `qml6glsink`, пауза GUI и память на ARM, многочасовой прогон, Ethernet между платами.
- Плато памяти: многочасовой прогон на x86 этой сессией не повторялся, его место — на Pi 4.
- Закупка по PRE-CAD и испытания L4.

## Наблюдения для следующих шагов

- В русском интерфейсе десятичный разделитель — точка (`75.6 °C`). Для RU принята запятая. Числа форматируются в QML через `toFixed`; нужен формат с учётом языка интерфейса.
- В рабочей копии ветки `v2` остались неотслеживаемые каталоги прежней разработки (`analysis/`, `armbian/`, `legacy-vendor-services/`, `radio/`, `reference/`) — следы checkout ветки `main`. В `v2` они не входят. По D5 их не переносят и не добавляют в коммиты.
