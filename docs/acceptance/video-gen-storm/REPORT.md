# Видео без входа, джиттер-буфер, перебор режимов auto — приёмка на платах (DEV deploy)

**Дата:** 2026-10-31 · **Ветка:** `claude/video-gen-storm` (`ff19d9f`, `678453b`) · **Образ плат:** `c0c509c` ·
**Выпуск:** DEV `0.1.0~dev0+g678453bd653b` на pi1 и pi2 · **Аренда:** `jitter-sweep` · **Полномочия:** владелец в
чате — «все по очереди делай», «Да, раскатывай». Идеи — разбор YStreamer (YLabs-FPV, GPL-3.0), код не заимствован.
**Источник:** HDMI devbox → MS2130 → USB 3.0 pi2, 1280×720@60 YUYV.

## 1. Лавина поколений без входа

Причина (стенд 2026-10-31, 126 поколений за 10 мин без MS2130): агент блока повторял `start` раз в 2 с (5 раз, затем
пауза 30 с), а `video-renew` пульта раз в 10 с обходил паузу. Исправление — контракт v13 §6: при `no-device` входа
(`Ingest`) агент закрывает поколение (`stop`, `video-stop` с причиной) и ждёт источник; пауза между неудачами 2, 4,
8, 16, 30 с; `video-renew` под той же паузой.

Испытание: программное отключение MS2130 (`/sys/bus/usb/drivers/usb/unbind 2-2` на pi2) на 120 с, затем `bind`.

| | До (`c0c509c`) | После (`g678453b`) |
|---|---|---|
| `video-key` за испытание | 25 | 2 (одно — до того, как Ingest увидел `no-device`; одно — «source back») |
| `video-renew` пульта | 12 | 1 |
| `video-stop` с причиной | — | `source unavailable: no-device` |
| «Нет видео» после отключения | 3,5 с | 3,6 с |
| Видео после возврата устройства | вернулось (замер не засёк) | 3,7 с |

`check_video_link` на выпуске: 9/9 PASS; «захват → декодирован» p50 43,7 мс, p95 46,3 мс; ctl-loss — «нет видео»
2,27 с, видео снова 2,11 с.

## 2. Джиттер-буфер rx: изменений нет

`SHEREGESH_VIDEO_JITTER_MS` пульта через временный drop-in `/run/systemd/system/sheregesh-video-rx.service.d/`
(корень плат только для чтения: первая попытка через `/etc` молча не записалась — те четыре прогона фактически при 20 мс
и годятся как оценка шума: p50 42,5–44,0 мс).

| Задержка буфера | p50 | p95 | max | потери / разрывы |
|---|---|---|---|---|
| 20 мс | 43,8 | 46,0 | 53,3 | 0 / 0 |
| 10 мс | 43,9 | 46,3 | 55,3 | 0 / 0 |
| 5 мс | 43,7 | 46,4 | 52,4 | 0 / 0 |
| 2 мс | 43,5 | 45,9 | 51,4 | 0 / 0 |

Задержка от буфера не зависит: без пропусков в последовательности `rtpbin` пакеты не задерживает. 20 мс оставлено —
запас на перестановки пакетов на радиоканале. 0 мс не измерено: пятый перезапуск rx подряд упёрся в лимит systemd
(StartLimit); отказ сброшен, drop-in удалён, служба в исходном состоянии.

## 3. Перебор режимов «auto»

`videoinput.auto_modes` (первый кандидат — прежний `auto_mode`) и `ModeMemory` службы tx: режим без первого кадра при
подключённом устройстве следующее поколение пропускает, давший кадр — первым. Проверено юнит-тестами
(`tests/unit/test_video_mode_memory.py`); на платах не воспроизводится — MS2130 первый кандидат отдаёт сразу.
