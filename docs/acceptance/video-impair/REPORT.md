# Видео SRTP под искажениями канала (tc netem)

**Дата:** 2026-10-31 · **Коммит:** `14eb957` · **Где:** devbox, контейнер Debian trixie (`tools/dev/netem-video`),
`tc netem` на `lo` своего сетевого пространства; конвейеры `sheregesh.videosvc.pipelines` (`selftest impair
--via=direct --seconds=20`): videotestsrc 640×360@30, x264enc, SRTP AES-128-GCM, rtpbin (AVPF, PLI), avdec_h264.
Уровень — L3 (контейнер; кодек и декодер программные, не Pi 4). Системный тест того же сценария через прокси —
`tests/system/test_videosvc_srtp_loopback.py` (1 % / 5 % и 3 % / 10 % / повторы 2 %).

## Результат (джиттер-буфер rx 20 мс — значение службы)

| Профиль netem | к/с | 1-й кадр, с | Наиб. разрыв, с | Потеряно (rtpbin) | PLI rx/tx | Джиттер, мс | Ошибки |
|---|---|---|---|---|---|---|---|
| без искажений | 30,06 | 0,04 | 0,020 | 0 | 1/1 | 0,1 | 0 |
| delay 5±2 мс, loss 1 %, reorder 5 % | 30,04 | 0,06 | 0,080 | 23 | 35/35 | 1,0 | 0 |
| delay 5±2 мс, loss 3 %, reorder 10 %, duplicate 2 % | 30,06 | 0,24 | 0,081 | 91 | 93/90 | 0,7 | 0 |
| пачки потерь (gemodel 1 % / 20 % / 70 %) | 29,96 | 0,04 | 0,061 | 92 | 50/46 | 0,1 | 0 |
| loss 5 % | 30,06 | 0,04 | 0,080 | 190 | 136/125 | 0,1 | 0 |
| delay 20±10 мс (normal), без потерь | 30,08 | 0,48 | 0,060 | 62 | 175/174 | 9,1 | 0 |

Поток при всех профилях не прерывается: частота 30 к/с, наибольший разрыв между кадрами ≤ 0,08 с, конвейер без
ошибок; на потерю приёмник отвечает PLI, кодер — ключевым кадром. Повторы (duplicate) отбрасывает защита SRTP от
повтора без ошибок. Число выданных кадров не отражает порчу изображения: декодер маскирует её до IDR по PLI.

## Найдено: джиттер-буфер 20 мс при неравномерной задержке

| Профиль delay 20±10 мс | PLI за 20 с |
|---|---|
| буфер 20 мс | 142–175 |
| буфер 50 мс | 9 |
| буфер 80 мс | 2 |

Опоздавшие сверх задержки буфера пакеты выбрасываются как потерянные — приёмник запрашивает ключевой кадр
~8 раз в секунду (поток ключевых кадров, рост битрейта). На проводной сети стенда (джиттер 0,5 мс) 20 мс верны и
задержку не увеличивают (video-gen-storm); для радиоканала с неравномерной задержкой буфер задаётся
`SHEREGESH_VIDEO_JITTER_MS` (служба rx) — по замеру этого канала, ориентир 50–80 мс. Ограничения частоты PLI на
передатчике нет — кандидат на доработку при испытаниях радиоканалов (этап B).

## Не проверено

Pi 4 с аппаратными v4l2h264enc/dec под искажениями, реальный радиоканал, качество изображения (метрика порчи кадров).
