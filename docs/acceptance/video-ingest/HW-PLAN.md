# VIDEO INGEST — план аппаратной приёмки устройств захвата (QA)

Ветка `qa/video-ingest` (база `v2` 43ea9a9), 2026-10-25. Перечень устройств и их статусы —
[`docs/hardware/VIDEO_CAPTURE_COMPAT.md`](../../hardware/VIDEO_CAPTURE_COMPAT.md). Требования и пороги —
[`MATRIX.md`](MATRIX.md).

> **Обновление S4 (2026-10-25, v2 59ea0c2):** утилиты образов, CVBS PAL/NTSC, режимы HDMI, нагрузка CPU и выбор
> источника файлом `video-input.json` + SIGHUP — [`../s4-video/USB-DIAG.md`](../s4-video/USB-DIAG.md). P4 снят
> (юнит править не нужно); §5 п.3 снят (`gui_capture.py --by video`); P3 — модули есть в образе как файлы.

Это не приёмка требований SRS: устройства захвата в SRS 1.0 не входят. Итог плана — карточка устройства в перечне
совместимости и инженерный вывод для B (видео на блоке) и C (GUI).

## 0. Условия

- **Только по разрешению владельца в чате** и после доставки устройств (27.10.2026). Разрешение — на каждую плату
  отдельно: pi2 (захват подключается сюда), pi1 (снимок GUI с остановкой службы пульта).
- Никаких действий OTA параллельно. Если на любой плате OTA ∉ {IDLE, COMMITTED, ROLLED_BACK} — STOP.
- Без root и sudo, только права `sheregesh-ui` (группа `video`, polkit `manage-units` для служб `sheregesh-*`,
  [`../e2e/MATRIX.md`](../e2e/MATRIX.md) §3.1). Юниты и образ не меняются.
- Длительных прогонов нет: устройство — **не более 10 минут**. Подготовка (P0–P4) — один раз, около 5 минут.
- Карту памяти плат в Mac не вставлять.
- `v4l2-ctl` в образе нет (пакета `v4l-utils` нет — `tools/image/build_deb.py`, S3.3 §1). Вместо него —
  [`tools/probe/video_hw_probe.py`](../../../tools/probe/video_hw_probe.py): стандартная библиотека Python и
  `gst-launch-1.0` из образа. Тесты — `tests/unit/test_vi_qa_video_hw_probe.py`. Для узлов `uvcvideo` дополнительно
  есть штатная диагностика `python3 -m sheregesh.videoinput` (она видит только `uvcvideo`).

```bash
cd ~/Developer/sheregesh
PI1=192.168.1.92  PI2=192.168.1.171          # проверить: после OTA адрес по DHCP мог смениться
DEV=ms2109                                    # короткое имя устройства по итогу D1: ms2109 | ms2130 | utv007 | …
D=docs/acceptance/video-ingest/hw/$DEV; mkdir -p $D
R1="ssh sheregesh-ui@$PI1"  R2="ssh sheregesh-ui@$PI2"
scp tools/probe/video_hw_probe.py sheregesh-ui@$PI2:/tmp/   # /tmp — tmpfs, после перезагрузки копию повторить
scp tools/probe/gui_capture.py sheregesh-ui@$PI1:/tmp/       # для D3v (снимок GUI пульта)
P="python3 /tmp/video_hw_probe.py"
```

## 1. Подготовка (один раз за сеанс)

DEV deploy на pi2 — только по решению владельца | выпуск и способ включения источника записаны в `p0-pi2.txt` | D5–D6 **BLOCKED** (D1–D4 выполняются: им нужно только ядро и `gst-launch`) |

Источники сигнала (записать в протокол, что было):
- HDMI — ноутбук или компьютер на выходе 1280×720 или 1920×1080, 60 Гц. На экране — **движущееся** изображение и часы
  с миллисекундами (полноэкранная страница с `Date.now()`). Неподвижная картинка неотличима от «застывшего» кадра (`frozen`).
- CVBS / S-Video — композитный источник: камера, видеоплеер, аналоговая FPV-камера на лабораторном питании.
  Действующие FPV-системы не подключать без решения владельца. **На стенде композитного источника нет:** если его не
  дадут, D3–D6 для аналогового захвата — BLOCKED (no source), выполняются только D1–D2.

## 2. Устройство — не более 10 минут

Порты Pi 4: USB 3.0 (синие) — для HDMI-захвата с заявленным USB 3.0; USB 2.0 (чёрные) — для аналогового.
Время по часам Mac записывается в `$D/steps.txt` у каждого шага.

это условие выполняется до снятия сигнала). Тайм-аут gui_capture после снимков 01/02 ожидаем: следующей фазе
нужна потеря связи, а здесь её нет. Код возврата ≠ 0 — не ошибка; доказательство — PNG.

**CAPS для D3–D4** — по выводу D2:
- MJPEG: `image/jpeg,width=1280,height=720,framerate=30/1` (повторить `1920x1080`, если позволяет время);
- YUYV: `video/x-raw,format=YUY2,width=W,height=H,framerate=F`;
- аналоговый PAL: `video/x-raw,format=YUY2,width=720,height=576,framerate=25/1`; NTSC: `…720,height=480,framerate=30000/1001`.
  Вход выбирается драйвером по умолчанию (обычно 0 — Composite). `v4l2src` вход не переключает; если D2 показал,
  что текущий вход не тот, — записать и подключать источник к входу по умолчанию.

## 3. Задержка — только оценка

Способ без дисплея (HDMI-источник, D3v): на ноутбуке полноэкранные часы с миллисекундами. В `states.json` gui_capture
есть время снимка по часам pi1. Задержка ≈ время снимка − показание часов в кадре. В оценку входят захват,
кодирование, сеть, декодирование и рендеринг; вывод на дисплей пульта не входит.

Погрешность — расхождение NTP Mac/ноутбука и pi1 (записать `chronyc tracking` или `timedatectl timesync-status` обеих
сторон, если доступно), шаг рендеринга кадра (~33 мс) и задержка экрана ноутбука. Порога в SRS нет — «измерено, без
критерия». Для аналогового источника способа нет: «не измерено».

## 4. Протокол и итог

- Сырые выводы — в `docs/acceptance/video-ingest/hw/<устройство>/`, итоговая таблица — `hw/RESULTS.md`
  (D1…D6: PASS / FAIL / BLOCKED с причиной).
- Карточка в `VIDEO_CAPTURE_COMPAT.md` заполняется из протокола (§5 перечня). Статус «проверено» — только при PASS D1–D6;
  с BLOCKED-шагами — «проверено частично» со списком.
- Отдельно для B: поведение без сигнала (D4), фактические режимы и форматы (D2), к/с (D3). Для C — что пульт показывает
  в D5/D6 и годится ли это как «нет сигнала» / «нет устройства».

## 5. Открытые вопросы

1. Где подключать захват в целевой схеме — к блоку (pi2, так в задании спринта) или к пульту (pi1, локальный вход
   S3.3)? План написан для pi2. Для pi1 шаги те же, только опрос в D5 по `ui-state.json` с `video.mode = local-input`.
2. Есть ли HDMI-выход у ноутбука стенда? Есть ли композитный источник? Без них D3–D6 — BLOCKED.
3. Снимок состояний «нет сигнала» и «нет устройства» на пульте: в `gui_capture.py` фазы привязаны к состоянию **связи**,
   а не видео. Нужен режим съёмки по `video.state` (запрос к C). Пока его нет, визуального доказательства для D5/D6
   нет — только `ui-state.json`, погрешность ≈ +1,3 с ([`../e2e/MATRIX.md`](../e2e/MATRIX.md) §2).
4. Цена покупки обоих устройств (в перечне — средняя по истории цен WB).
5. Комплектация HDMI-захвата: кабель USB-C→USB-A в карточке не указан.
