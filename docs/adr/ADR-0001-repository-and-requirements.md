# ADR-0001. Структура репозитория и единый источник требований

- **Статус:** Принято (TL-001, D5), 2026-10-22
- **Затронутые требования:** REQ-REL-001, REL-002, REL-009, DOC-001, DOC-006, DOC-007, REL-011

## Контекст

В комплекте Rev A требования жили в четырёх копиях: таблицы SRS, JSON, CSV и лист XLSX. Тестовые идентификаторы существовали в двух схемах (TEST-ID и T-01…T-10), реестры GAP — в двух несовместимых нумерациях. Репозиторий `v2` пуст и имеет независимую историю. Прежняя разработка отделяется (D5).

## Решение

**Структура:**

```text
docs/
  srs/            SRS (раздел 4 генерируется)
  requirements/   requirements.json — ЕДИНСТВЕННЫЙ источник; TEST-MATRIX.csv и CHANGELOG-REQ.md генерируются
  tests/          TEST-SPEC.md (генерируется), methods/ — подробные методики M/X
  hardware/       аппаратная спецификация, PRE-CAD-CHECKLIST, паспорта
  adr/            архитектурные решения
  decisions/      журнал решений D-NNN / TL-NNN
  security/       модель угроз, секреты, проверка прежней разработки
  audit/          аудит и реестр проблем AUD-NNN
  baseline/rev-a/ неизменяемая копия комплекта Rev A с SHA256SUMS
software/
  sheregesh/      общий Python-пакет: config, protocol, diag, ... (оба устройства)
  console/        пульт: GUI и службы
  remote/         удалённый блок: агент
  emulators/      безопасные эмуляторы
  image/          сборка образов
hardware/         bom/, cad/console, cad/remote
tests/            unit/ (L2), system/ (L3, эмуляторы), hil/ (L4, стенд), tools/
tools/            reqs/ (генератор реестра), release/
release/          шаблоны отчётов, журнал подписей, структура доказательств
```

**Правила реестра:**
1. Требования и испытания меняются только в `docs/requirements/requirements.json`. Производные файлы генерирует `tools/reqs/reqgen.py generate`; CI проверяет их актуальность (`generate --check`).
2. Любое изменение текста или приоритета требования относительно baseline Rev A должно иметь содержательную запись CHG. Генератор это проверяет (REQ-REL-009).
3. Статус PASS ставится только вместе со ссылкой на доказательство, версией ПО, HW-версией, датой, исполнителем и уровнем. Гейт `reqgen.py gate` реализует REQ-REL-001.
4. Один тест может покрывать несколько требований. Выведенные идентификаторы перечислены в `retired_tests` и повторно не используются.
5. Генератор и тесты используют только стандартную библиотеку Python — ради воспроизводимости без внешних зависимостей.

**Прежняя разработка (D5):** ничего не переносится автоматически. Если понадобится заимствование (например, приём «экран определяет устаревание данных»), оно записывается в `docs/migration/legacy-register.md` (REQ-DOC-007) и переписывается заново после проверки лицензии.

**Лицензирование:** формат REUSE — заголовки SPDX и каталог `LICENSES/`. ПО — GPL-3.0-or-later, CAD — CERN-OHL-S-2.0, документация — CC-BY-SA-4.0. Комплект Rev A в `docs/baseline/` — исходные материалы владельца; их лицензия указывается в REUSE.toml до публикации.

## Последствия

- BOM v0.4 больше не содержит матрицы требований.
- Предлагаемая структура совпадает с предварительной структурой владельца (`/docs`, `/software`, `/hardware`, `/tests`, `/tools`, `/release`). В пустом `v2` сохранять было нечего.
