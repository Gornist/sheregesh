# ADR-0002. Программная платформа и сборка образа

- **Статус:** Принято (TL-002), 2026-10-22. Условия подтверждения — пробы S2-1…S2-3 ниже.
- **Затронутые требования:** REQ-P-001, R-001, SYS-004, SYS-007, P-012, SW-001, UPD-001, DOC-006, REL-010
- **Связано:** ADR-0003 (GUI), ADR-0006 (обновления), AUD-008, AUD-026, AUD-028

## Решение

| Аспект | Выбор | Обоснование |
|---|---|---|
| ОС | **Raspberry Pi OS Lite, 64-бит (arm64)**, текущий стабильный выпуск на базе Debian 13 «trixie»; точная версия фиксируется в манифесте каждой сборки | Требование P-001/R-001; Lite — без рабочего стола, меньше памяти и время загрузки |
| Сборка образа | **`rpi-image-gen`** (официальный инструмент Raspberry Pi); запасной вариант — `pi-gen` | Декларативные конфигурации, собственная разметка разделов, сборка в CI. Выбор подтверждается пробой S2-1 |
| Разметка | boot A/B, rootfs A/B (ext4, монтируется только для чтения), data (ext4) — ADR-0006 | UPD-001, AUD-026 |
| Графическая сессия | **cage** (Wayland-киоск, одно приложение) без рабочего стола; автозапуск через systemd от непривилегированного пользователя `sheregesh-ui` | P-012 (≤ 15 с), минимум зависимостей |
| Язык | **Python 3** из дистрибутива для служб и GUI; C/C++ — только при доказанной необходимости по профилированию | Поддерживаемость, тестируемость на x86 (L2/L3) |
| Службы | systemd units с `WatchdogSec`, `Type=notify`, отдельными пользователями и `ProtectSystem=strict` | SW-001 |
| Межпроцессный обмен | Unix-сокеты с JSON-сообщениями (тот же формат, что в ADR-0007) | Единый формат, простая эмуляция |
| Журналы | journald, хранение на разделе data, `SystemMaxUse=200M`; экспорт с фильтром секретов | SW-001/005, ресурс SD |
| Пакеты | Собственное ПО — Debian-пакеты (`arch: all`), собранные в CI; зависимости — только из репозиториев Debian и Raspberry Pi OS, без `pip` в образе | Воспроизводимость, SYS-004 |
| Воспроизводимость | Манифест сборки: версии и SHA-256 всех пакетов. Использованные `.deb` архивируются с каждым релизом, потому что archive.raspberrypi.com не хранит старые версии. `SOURCE_DATE_EPOCH` | DOC-006, REL-010 |
| Сеть | Статическая адресация лабораторного канала (ADR-0007); Wi-Fi и Bluetooth выключены оверлеями `disable-wifi` и `disable-bt` | 1.0 работает только по проводу; меньше поверхность атаки |
| Доступ | Паролей и SSH по умолчанию нет; SSH только в dev-режиме по ключу | AUD-028 |
| Время | `fake-hwclock`; удалённый блок синхронизируется с пультом (chrony по лабораторному каналу); RTC — по решению AUD-012 | ADR-0005 §4 |

## Пробы на Pi 4 (этап S2) — условие подтверждения

| Проба | Что подтвердить | Если не подтвердится |
|---|---|---|
| S2-1 | `rpi-image-gen` собирает образ с разметкой ADR-0006 в CI (arm64) | Использовать `pi-gen` и собственный скрипт разметки |
| S2-2 | Холодная загрузка до интерактивного GUI в cage ≤ 15 с (P-012, Should) | Зафиксировать факт; оптимизировать порядок служб |
| S2-3 | Пакеты PySide6 (Qt 6 QML) доступны в выпуске для arm64 и работают под cage | ADR-0003: перейти на PyQt6 из Debian (тоже совместим с GPLv3) |

## Отклонённые варианты

- **Yocto/Buildroot:** лучшая воспроизводимость, но это не Raspberry Pi OS (противоречит P-001/R-001) и слишком дорого в сопровождении.
- **Полный рабочий стол (labwc и панель):** дольше загрузка, лишние функции, сложнее изоляция.
- **Контейнеры (Docker) на устройстве:** лишний слой и расход памяти; A/B решает задачу атомарности обновлений.

## Реализация S2-1 (2026-10-23)

Сборка — `os/build.sh` (`rpi-image-gen`, коммит закреплён в `os/rpi-image-gen.ref`), CI — `.github/workflows/image.yml` на нативном `ubuntu-24.04-arm`. Решения ADR не меняются; отклонения в деталях:

- **База.** Состав, равный Raspberry Pi OS Lite trixie arm64 (Debian trixie + архив Raspberry Pi, слои `rpi-*`), собирается слоем `sheregesh-base` без `openssh-server`, `iwd` и беспроводных регуляторных пакетов: SSH по умолчанию отсутствует (AUD-028), Wi-Fi и Bluetooth — `dtoverlay=disable-wifi`/`disable-bt`.
- **Время.** В trixie стек Raspberry Pi OS маскирует `fake-hwclock`. Ту же функцию — время не раньше последнего сохранённого — выполняет файл часов `systemd-timesyncd` в `/var/lib/systemd/timesync/clock` (засевается `SOURCE_DATE_EPOCH`). Без сети NTP недоступен; RTC — по решению AUD-012.
- **Службы.** `sheregesh-console.service` (cage, пользователь `sheregesh-ui`) и `sheregesh-remote-emu.service` (лабораторный эмулятор, `DynamicUser`, `IPAddressAllow=localhost`). `Type=notify` и `WatchdogSec` пока не реализованы в пульте — `Type=simple` до S3.
- **Пакет.** `sheregesh_*_all.deb` собирается детерминированно `tools/image/build_deb.py` (без dpkg-deb), переводы `.qm` — в пакете.
- **PySide6.** В trixie — PySide6 6.8.2, а разработка и CI идут на 6.12. В контейнере trixie arm64 пульт на 6.8.2 отрисовал все экраны демонстрационного сценария без ошибок QML (offscreen). Подтверждение под cage на Pi — проба S2-3.
- **Dev-вариант** (`sheregesh-lab-dev-pi4`) — для проб в локальной сети владельца: DHCP и SSH только по открытому ключу, root и пароли заблокированы, sudo нет. Не для релизов.
- **Воспроизводимость.** Манифест в образе (`/usr/share/sheregesh/image-packages.tsv`: пакет, версия, SHA-256 из индекса). Архив использованных `.deb` с каждым релизом (REL-010) пока не реализован: archive.raspberrypi.com не хранит старые версии, поэтому повторная сборка через время может дать другие версии. Это открытый пункт до первого релиза.
