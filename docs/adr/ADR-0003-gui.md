# ADR-0003. Графический интерфейс пульта

- **Статус:** Принято (TL-002), 2026-10-22. Состав экранов — предложение Tech Lead (AUD-032); работа идёт по нему, пока владелец не примет иного решения.
- **Затронутые требования:** REQ-P-002, P-003, P-011, P-012, UI-001…UI-007, SYS-009, SW-002, SW-004, PWR-007

## Решение

**Технология:** Qt 6 / QML, Python-привязки PySide6 (запасной вариант — PyQt6, проба S2-3). Одно окно 1920×1200 в cage.

**Разделение:** GUI — тонкий клиент без прав root. Всё состояние и все действия проходят через службы (`sheregesh-core`, ADR-0004/0007) по Unix-сокету. GUI не пишет файлы конфигурации и не вызывает системных команд. Если служба недоступна, GUI показывает это состояние, а не последнее известное значение (принцип PWR-007).

**Экраны 1.0:**
1. Статус системы (оба устройства);
2. Видео;
3. Диагностика (службы, сеть, питание, температура, вентилятор);
4. Журналы (просмотр и экспорт);
5. Настройки (профили, применение, подтверждение, откат);
6. Резервное копирование и восстановление;
7. Обновление (оба устройства);
8. Справка;
9. О системе (паспорт обоих устройств);
10. Меню питания.

Критичные экраны для P-003 — 1, 3, 5, 7, 10; перечень фиксируется в `docs/ui/critical-screens.md`.

**Ввод:**
- Навигация полностью фокусная. Все действия выполняются клавишами `Up/Down/Left/Right/Enter/Escape/Menu`; сенсор — дополнительный способ.
- Физические органы выдают стандартные события evdev: оверлеи `gpio-keys`/`rotary-encoder` или готовая USB HID-клавиатура. Выбор SKU по AUD-021 на работу GUI не влияет.
- Сенсор — USB HID multitouch.
- Кнопка питания — `gpio-shutdown` / GPIO3 (AUD-022); короткое и длинное нажатие обрабатывает служба питания, GUI показывает диалоги.

**Изменяющие действия (SYS-009):** каталог `docs/ui/state-changing-actions.md`. Каждое действие идёт через единый компонент подтверждения. Экраны только для чтения проверяются автотестом обхода дерева QML.

**Локализация:** `qsTr` и файлы `.ts`; CI проверяет, что непереведённых строк RU/EN 0. Справка — Markdown, собирается в HTML при сборке пакета и показывается внутри приложения без браузера.

**Темы и масштаб:** QML-синглтон палитры (светлая и тёмная, контраст ≥ 4,5 : 1) и свойство масштаба 100/125/150 %, применяемое без перезапуска. Глобальный `QT_SCALE_FACTOR` не используется.

**Видео (SW-002):** GStreamer — RTP H.264 → аппаратный декодер `v4l2h264dec` → `qml6glsink` в QML-элементе. Если элемент недоступен или производительности не хватает — запасной путь `appsink` → `QVideoSink` (проба S2-4).

**Гашение экрана (UI-005):** таймер бездействия в GUI. Отключение экрана — через протокол управления питанием вывода композитора (`wlopm`), а при отсутствии поддержки — чёрный экран. Первый ввод после пробуждения поглощается. Поведение HDMI-дисплея проверяется пробой H1 (AUD-025).

**Тестирование:**
- `pytest-qt`, платформа `offscreen`;
- скриншоты 2 тем × 3 масштабов × 2 языков;
- автоматическая проверка геометрии (элементы в границах, без перекрытий интерактивных);
- навигация эмуляцией клавиш;
- на стенде — `uinput` для физических событий.

## Пробы
- **S2-3** — PySide6 под cage (ADR-0002).
- **S2-4** — 1920×1200 QML плюс аппаратное декодирование H.264 720p30: ≥ 29 к/с при загрузке CPU ≤ 60 %.

## Отклонённые варианты
- **GTK4:** нет готового аппаратного видео в сцене, слабее сенсорные сценарии.
- **Браузерный GUI (Chromium в киоске):** память и время загрузки, лишний веб-стек; веб-интерфейс отложен до v1.1.
- **Flutter / Kivy:** меньше зрелости на Pi OS, нет пакетов дистрибутива.
