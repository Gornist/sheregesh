# ADR-0006. A/B-обновления, откат и восстановление

- **Статус:** Принято (TL-002), 2026-10-22. Условие — проба S2-5 (tryboot + RAUC на Pi 4).
- **Затронутые требования:** REQ-UPD-001…UPD-006, CFG-006, REC-001, REC-002
- **Связано:** ADR-0005 (ключи), ADR-0004 (конфигурация), AUD-013 (dev-режим), AUD-014 (откат версии)

## Решение

**Механизм:** RAUC (пакет Debian `rauc`) с кастомным загрузочным бэкендом поверх штатного механизма прошивки Pi 4 **tryboot** (`autoboot.txt`, `tryboot_a_b=1`). U-Boot не используется: прошивка сама загружает новый слот один раз, а при сбое или перезагрузке без подтверждения возвращается на прежний.

**Разметка (GPT) [проба S2-5]:**

| № | Раздел | ФС | Назначение |
|---|---|---|---|
| 1 | autoboot | FAT, 32 МБ | `autoboot.txt` — выбор загрузочного раздела |
| 2 | boot-A | FAT, 256 МБ | Ядро и прошивка слота A |
| 3 | boot-B | FAT, 256 МБ | Ядро и прошивка слота B |
| 4 | root-A | ext4, только чтение | Корневая ФС слота A |
| 5 | root-B | ext4, только чтение | Корневая ФС слота B |
| 6 | data | ext4 | Конфигурация, секреты, журналы, keyring CRL, доказательства тестов |

Корневая ФС монтируется только для чтения; изменяемые каталоги (`/var/tmp`, кэши) — tmpfs. `/var/log/journal` и `/data` лежат на разделе data.

**Установка (UPD-001…004):**
1. Бандл проверяется по цепочке до закреплённого корня и CRL (ADR-0005), `compatible`, а после решения AUD-014 — и версия.
2. Запись идёт только в неактивную пару boot/root.
3. Перезагрузка в режиме `tryboot` в новый слот.
4. `sheregesh-health.service`: обязательные службы active, связь с конфигурацией (ADR-0004), автотест платформы. При успехе — `rauc status mark-good` и обновление `autoboot.txt`. При провале — перезагрузка; прошивка возвращается на прежний слот (не более 2 попыток загрузки, UPD-004).
5. Событие записывается в журнал и показывается в GUI.

**Удалённый блок:** пульт передаёт бандл агенту (ADR-0007). Удалённый блок **сам** проверяет подпись своим закреплённым корнем; пульт не является доверенным посредником.

**Безопасный режим (REC-001/002):** `sheregesh-safe.target` загружается, если раздел data не монтируется или проверка ФС (`fsck -n`) находит ошибки.
- Режим даёт: диагностику, экспорт читаемых данных на USB с манифестом, инструкции RU/EN.
- `mkfs` и исправляющий `fsck` без явного подтверждения пользователя не запускаются никогда.
- На пульте режим показывается в GUI. Удалённый блок сообщает о нём пульту и индикатором; без связи с пультом — инструкция сервисного доступа.

**Носитель восстановления:** подписанный rescue-образ на USB (P-17) — переустановка на новый носитель (REC-002).

**Dev-режим (UPD-005/006):** механизм зависит от решения AUD-013 (у RAUC нет режима установки неподписанного бандла). Рекомендация — однократное доверие ключу разработчика, внесённому локально с физическим подтверждением. До решения реализуется всё остальное. Откат в dev-режиме — тот же механизм tryboot (UPD-006).

## Проба S2-5
Цикл tryboot → mark-good и tryboot → сбой → возврат на Pi 4 с текущим EEPROM. Проверяется 20 циклов, включая отключение питания на каждом этапе.

## Отклонённые варианты
- **U-Boot + RAUC / SWUpdate / Mender:** лишний загрузчик при наличии штатного tryboot; Mender ориентирован на сервер.
- **OSTree:** другая модель обновления, хуже сочетается с Raspberry Pi OS и требованием раздельных слотов.
