# ADR-0007. Лабораторный обмен между устройствами и управление удалённым блоком

- **Статус:** Принято (TL-002, D3), 2026-10-22
- **Затронутые требования:** REQ-SYS-002, SYS-007, SYS-008, SW-002, SW-003, SW-004, UI-004, UI-006, CFG-008, REC-002, REL-004, REL-005

## Решение

**Канал:** прямой Ethernet-кабель в изолированном стенде. Статические адреса: пульт 192.168.77.1/24, удалённый блок 192.168.77.2/24; без шлюза и DNS. Сетевой коммутатор не обязателен.

**Протокол управления** `SHRG-LAB`. Описание — `docs/protocol/PROTOCOL.md`, создаётся на этапе S1.
- TCP, порт 7700. Удалённый блок — сервер (агент), пульт — клиент.
- Сообщения: JSON UTF-8, по одному на строку: `{"proto": "1.0", "type", "seq", "ts", "body"}`.
- Рукопожатие `hello` в обе стороны:
  - версия протокола MAJOR.MINOR, версия ПО (SemVer), HW-версия, тип и ID устройства;
  - **правило совместимости (CHG-012):** одинаковый поддерживаемый MAJOR, MINOR второй стороны не ниже минимума матрицы, ПО не в списке отклонённых, допустимая HW-версия; сессия работает на MAJOR.min(MINOR); сообщения новее версии сессии не исполняются. Иначе отказ с сообщением; после отказа разрешены только `hello` и `bye`.
  - Матрица `software/sheregesh/compat-matrix.yaml` задаёт поддерживаемые версии и ограничения ПО/HW (SYS-008).
- Heartbeat раз в 1 с. При отсутствии 3 с — состояние «нет связи» (критерий ≤ 5 с). Клиент переподключается с задержкой 1 → 2 → 4 с, но не реже раза в 4 с (критерий восстановления ≤ 10 с).
- `seq` монотонен; приёмник считает пропуски и нарушения порядка (SYS-002, link-test).
- Объёмные передачи (бандл обновления, архив конфигурации, экспорт журналов) идут отдельным TCP-соединением: `{"size", "sha256"}`, затем данные; приёмник проверяет хеш.

**Команды агента** (D3 — всё управление удалённым блоком идёт через пульт):

| Команда | Изменяет состояние | Подтверждение на пульте (SYS-009) |
|---|---|---|
| `status.get`, `passport.get`, `services.get`, `power.get`, `thermal.get` | Нет | — |
| `config.get`, `config.apply`, `config.rollback`, `config.backup`, `config.restore` | `apply`, `rollback`, `restore` — да | Да |
| `logs.export` | Нет | — |
| `update.install` | Да | Да |
| `power.shutdown`, `power.reboot` | Да | Да |
| `indicator.test` | Нет (временно) | — |
| `devmode.enable` | Да | Да, плюс физическая кнопка пульта (UPD-005) |

Каждая изменяющая команда записывается в журналы обоих устройств с `seq` и результатом.

**Видео (SW-002):** RTP/UDP, H.264, 1280×720 @ 30 к/с, порт 5600, от удалённого блока к пульту; фиксированные caps. Источник — `videotestsrc` и аппаратный `v4l2h264enc`. На пульте есть локальный генератор для работы без удалённого блока.

**Индикатор удалённого блока (UI-004, D3):** RGB за световодом. Таблица состояний — `docs/ui/status-indicator.md`, создаётся на этапе S1. Базовые состояния: загрузка, норма, нет пульта, применение или обновление, безопасный режим, неисправность.

**Безопасность канала:** аутентификации и шифрования в 1.0 нет — это допустимо только на изолированном стенде и документируется как ограничение 1.0 (AUD-028). Обновления защищены независимо: удалённый блок сам проверяет подпись (ADR-0006).

**Без операционной функциональности:** протокол не содержит команд управления внешними аппаратами, радиомодулями или исполнительными устройствами (`docs/security/out-of-scope-components.md`).

## Отклонённые варианты
- **gRPC / protobuf:** тяжелее зависимости и отладка, выгоды при таком объёме нет.
- **MQTT:** нужен брокер — лишний компонент.
- **SSH как канал управления:** смешивает доступ разработчика и протокол продукта, хуже тестируется эмулятором.
- **mDNS-обнаружение:** не нужно при двух узлах со статическими адресами; при необходимости добавляется в MINOR.

## Реализация S1.5 (2026-10-23)

- Канал реализован между двумя процессами на `127.0.0.1` (`software/sheregesh/link/`, `software/remote/sheregesh_remote/`). Обе стороны отказываются работать не через loopback.
- Типы сообщений версии 1.0: `hello`, `heartbeat`, `status`, `event`, `error`, `bye`. Строка не длиннее 64 КиБ; проверяются поля `proto/type/seq/ts/body`; состояние второй стороны разбирается как недоверенные данные.
- В S1.5 команды агента из таблицы выше **не реализованы**: удалённый блок только сообщает синтетическое состояние, а от пульта принимает `hello` и `bye`. Остальные сообщения учитываются и не исполняются. Команды управления конфигурацией, обновлением и выключением блока появятся на этапе S5 с подтверждением на пульте.
- Пороги: «нет связи» — при отсутствии heartbeat дольше `heartbeat_timeout_s` (3 с); `PEER-SLOW` — при возрасте больше половины таймаута; после 10 повреждённых сообщений подряд соединение переустанавливается; переподключение — 0,5 → 1 → 2 → 4 с.
