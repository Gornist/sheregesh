# ADR-0008. Эмуляторы и уровни испытаний

- **Статус:** Принято (TL-002), 2026-10-22
- **Затронутые требования:** REQ-UI-003, PWR-007, SW-003, SW-004, SW-005, REL-001; все Must с методом A

## Решение

**Аппаратные абстракции.** Службы работают с интерфейсами, у каждого из которых есть реальная реализация и эмулятор:

| Интерфейс | Реальная реализация (позже) | Эмулятор (`software/emulators/`) |
|---|---|---|
| `Peer` (второе устройство) | TCP SHRG-LAB | Эмулятор агента удалённого блока: настраиваемые версии, задержки, разрывы, неисправности |
| `PowerProvider` | Драйвер выбранного модуля (AUD-001) | Сценарии разряда, переключение источника, сигнал низкого заряда, состояние «недоступно» |
| `TemperatureSource`, `FanController` | sysfs/`vcgencmd`, PWM и тахо | Кривые температуры, потеря тахосигнала, потеря PWM |
| `Indicator` | RGB-модуль | Запись состояний для сверки с таблицей |
| `VideoSource` | GStreamer `videotestsrc` + кодер | То же на x86 (программный кодер) |
| `FaultInjector` | — | Коды из `docs/ui/fault-catalog.md` |

Выбор реализации — через конфигурацию службы. Реальные драйверы появляются после выбора оборудования, не блокируя ПО.

**Уровни испытаний:**

| Уровень | Где | Что |
|---|---|---|
| L2 | CI (x86, arm64) | Модульные тесты библиотек |
| L3 | CI | Системные тесты: процессы пульта и удалённого блока на одном хосте через localhost, эмуляторы, offscreen GUI |
| L4 | Стенд STAND-1, self-hosted runner (только защищённые теги и ветки или ручной запуск, без секретов) | Те же сценарии на эталонном оборудовании; ручные M-испытания по TEST-SPEC |
| L5 | Внешний исполнитель | DOC-008 |

**Учёт доказательств.** Автотесты помечаются TEST-ID (маркер `@pytest.mark.test_id("TEST-CFG-002")`) и пишут JSON-отчёт с версией ПО, HW-версией и временем. Статус в реестре меняется только PR, который добавляет ссылку на сохранённый отчёт в `release/evidence/<версия>/` (или вложение релиза). Автоматического перевода в PASS нет: результат L3 не равен PASS для Must, требующего L4.

## Последствия
- На этапе S1 эмуляторы и библиотеки разрабатываются на x86 без оборудования.
- Реальные драйверы питания и вентилятора ждут решений по оборудованию, но интерфейс уже зафиксирован.
