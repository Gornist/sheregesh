# ADR-0017. Время между платами без интернета: пульт — источник времени блока (chrony)

- **Статус:** Предложено, реализовано в исходниках 2026-10-29; на платах — после образа и OTA (отчёт приёмки).
- **Решение владельца 2026-10-29:** пункт 1 из обсуждения — пульт отдаёт время блоку по chrony; отметка времени в
  `/persistent` и модуль RTC — отдельными решениями.
- **Связано:** ADR-0016 (метрика `latency_ms` сравнивает часы двух плат), ADR-0007 (mTLS: сроки сертификатов),
  ADR-0006/0009 (образ, слоты, OTA). Требования не меняются.

## 1. Контекст

На платах `systemd-timesyncd` с пулом `2.debian.pool.ntp.org`, у Pi 4 нет RTC. На стенде платы синхронны с
интернетом (4–7 мс до сервера), но в работе доступа к интернету не будет: каждая плата пойдёт своим ходом от
последней отметки времени, расхождение — секунды и больше. Это ломает метрику задержки SRTP (метка блока ↔ часы
пульта), сопоставление журналов двух плат и может ломать mTLS (часы раньше `notBefore`: после пробной загрузки
pi2 журнал ядра начинался 13 апреля).

## 2. Решение

1. **chrony вместо timesyncd** (зависимость пакета `sheregesh`, `systemd-timesyncd` маскируется). `chrony.conf`
   образа не содержит источников: роль платы известна только при работе. `makestep 1 -1` — шаг в любой момент
   (часы без RTC после простоя), `cmdport 0` — команды только через локальный сокет, `allow` только localhost
   (чтобы chronyd открыл порт сервера).
2. **Роль** (`sheregesh-time role`, юнит `sheregesh-time-role.service` после `chrony.service`,
   `PartOf=chrony.service`). Источники — файлы в `sourcedir /run/sheregesh-time/sources` (`role.sources`,
   `session.sources`) и `chronyc reload sources`: имена резолвит chronyd сам, с повторами. Через chronyc — только
   `local`, `allow`, `reload` (стенд 2026-10-29: `chronyc add pool` резолвит имя сам — в песочнице юнита и без
   интернета отказ, и роль не применялась целиком). AppArmor на платах выключен; профиль chronyd Debian/Ubuntu этот
   каталог не разрешает — при включении AppArmor нужен локальный профиль (так проявилось в контейнере на devbox).
   - пульт: `pool 2.debian.pool.ntp.org iburst` (если интернет есть), `local stratum 10` (если нет — пульт сам
     себе источник), `allow` адресам `peer_hosts` из `link.json`;
   - блок: `server <peer_hosts> iburst minpoll 4 maxpoll 6`, **без пула** — часы блока следуют пульту, а не
     интернету: важна согласованность плат между собой.
3. **Адрес сеанса** (DHCP может отличаться от `peer_hosts`): `sheregesh-time-peer@<адрес>.service` (root, oneshot),
   sheregesh-ui может только «start» (polkit, как `sheregesh-video-allow@`). Запускают пульт — при переходе канала
   mTLS в `connected` (адрес блока), агент блока — после совместимого `hello` в сетевом профиле (адрес пульта).
   Пульт: `chronyc allow`; блок: адрес — источник (`session.sources` заменяется целиком). Вызов — в потоке, ошибка
   сеансу не мешает (итог в журнал).

4. **Часы при загрузке без RTC** (стенд 2026-10-29: pi2 на новом образе при старом пульте загрузилась с часами
   13 апреля — раньше `notBefore` сертификатов, mTLS не поднялся, confirm не прошёл; timesyncd раньше переводил часы
   по своему файлу-отметке, chrony этого не делает). chronyd запускается с `-s` — часы ставятся по mtime drift-файла;
   drift-файл — в общем `/persistent/chrony` (один на оба слота: время не откатывается после OTA), каталог создаёт
   tmpfiles (`_chrony`), юниту chrony разрешена запись туда. `sheregesh-time save` продвигает mtime только вперёд —
   таймером раз в 10 мин и при выключении (как fake-hwclock): после потери питания часы отстают не больше чем на
   10 мин плюс время простоя.
5. **Порядок OTA:** сначала пульт (источник времени), затем блок.

## 3. Последствия

- Без интернета платы согласованы между собой (ожидаемо — доли миллисекунды в проводной сети); абсолютное время
  пульта после простоя отстаёт на время простоя (часы не идут назад, но и вперёд не знают) — RTC отдельным решением.
- Перезапуск chrony теряет сеансовый адрес до следующего сеанса (источники `peer_hosts` восстанавливает role).
- Порт NTP 123/udp открыт на обеих платах, отвечает пульт только блоку; блок клиентам не отвечает.
- Метрика задержки в приложении по-прежнему оценивает смещение по heartbeat; переход на PING/PONG с минимальным
  RTT — отдельно.
