# Спринт ADR-0016: видео как служба, SRTP по UDP

**Дата:** 2026-10-27 · **База:** `v2` `443ee8e` · **Контракт:** `docs/architecture/VIDEO-SERVICE-CONTRACT.md`

## Цель

Видео pi2 → pi1 идёт через службы `sheregesh-video-tx`/`-rx`: SRTP по UDP внутри GStreamer, ключи по SHRG-LAB 1.5
(mTLS), Python не трогает пакеты. Путь TLS (ADR-0011) остаётся резервным. Аппаратные кодер и декодер и путь GPU
(ADR-0015) не меняются.

## Уровни приёмки

| Уровень | Что должно работать | Как проверяем | Спринт |
|---|---|---|---|
| 0 — первый кадр | кадр SRTP с pi2 на pi1: модуль конвейеров, ключ вручную | `pipelines` локально на Mac (x264/avdec), затем на платах коротким прогоном | этот |
| 1 — продукт | службы, `video-key`, nftables, перезапуск GUI не рвёт видео, откат на TLS, задержка «отправка → декодирован» против TLS на чистой сети | CI + платы, 3 × 60 с | этот |
| 2 — потери | 0 % и 3 % потерь, одно физическое отключение Ethernet: видео не замирает целиком, восстановление ≤ 10 с | платы, `tc netem` на dev-образе | этот |
| 3 — выносливость | полная матрица потерь, 3 ч, все переходы OTA | платы | следующий |

## Этапы

0. **Контракт** — главный инженер. Готово: `VIDEO-SERVICE-CONTRACT.md` v1.
1. **Три трека параллельно** (файлы не пересекаются, контракт §9), каждый в своём worktree и ветке:
   A — конвейеры TX/RX с RTCP/PLI; B — сеанс, ключи, сокет управления, состояние; C — образ, юниты, nftables, polkit.
2. **Трек D** — точки входа служб `videosvc/tx.py`, `rx.py` (автомат состояний поверх A и B), после слияния A и B.
3. **Встраивание** — главный инженер: SHRG-LAB 1.5 в `link/codec.py`, `link/client.py`; агент → клиент `video-tx`;
   GUI → клиент `video-rx` и `unixfdsrc` с сокета службы. Перед этим — согласование с сессией S8 (те же файлы).
4. **Образ и платы** — главный инженер: сборка на devbox, OTA сначала pi2 (pi1 старый — проверка отката на TLS),
   затем pi1; уровни 0–2 на платах.

## Как работают исполнители

- **Opus (главный инженер):** контракт, приёмка каждого трека (чтение кода, запуск тестов), слияние, этапы 3–4,
  все работы на платах.
- **Sonnet, effort medium — руководитель трека:** получает трек целиком, режет его на задачи по одной функции или
  одному файлу для Haiku high, пишет каждой задаче точное ТЗ (сигнатуры, входы и выходы, тесты, что нельзя
  трогать), проверяет результат, собирает трек, гоняет тесты, коммитит в ветку трека, отчитывается.
- **Haiku, effort high:** одна узкая задача — одна функция или класс с тестами против готовой сигнатуры.
- **Платы субагентам недоступны.** Все прогоны на pi1/pi2 — только главный инженер, с таймаутом и проверкой
  `dmesg` (vchiq) и рабочего потока после каждого.

## Запреты стенда

`v4l2jpegdec`; `GST_TRACERS=latency` с аппаратным кодером; CBR; `v4l2convert` перед кодером; программный кодер
в основном режиме; ключи в `argv`, окружении, журналах, файлах; удаление пути TLS; изменение модели прав ради
удобства. Новые зависимости — только с записью в сборку (`build_deb.py`).
