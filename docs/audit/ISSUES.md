# Реестр проблем аудита «Шерегеш» 1.0 Rev. A

**Документ:** `AUDIT-ISSUES-001` · **Дата:** 2026-10-22 · **Статус:** ведущий реестр проблем. Решения D1–D5 приняты 2026-10-22; текущие статусы — в таблице ниже.
**База аудита:** `SHEREGESH-1.0-Rev-A-PACK.zip` (README, SRS Rev A, HARDWARE 1.0, BOM v0.3.xlsx, TEST-MATRIX.csv, REQUIREMENTS.json), ветка `v2`.
`Sheregesh-docs.docx` в комплект не входил и не анализировался.

Идентификаторы `AUD-NNN` введены, чтобы не путать их с `GAP-NNN`: в SRS и в BOM номера GAP означают разные вещи (см. AUD-010).

**Категории:**
- **BLOCKER** — без решения нельзя начинать соответствующую часть реализации (указано, какую).
- **IMPORTANT** — решить до завершения соответствующего этапа.
- **NON-BLOCKING** — можно отложить без нарушения Must 1.0.

**Кто решает:** «Владелец» — меняется стоимость, функциональность, безопасность или трактовка Must. «Tech Lead» — стандартное инженерное решение без изменения утверждённых требований (оформляется ADR/changelog, владелец уведомляется). «HW» — аппаратный инженер/CAD. «Питание» — профильный специалист по готовым аккумуляторным изделиям.

**Пометки:** [Ф] — факт из документов, [В] — инженерный вывод/оценка, требующий проверки.

## BLOCKER

### AUD-001 · Питание пульта: нет готового решения, удовлетворяющего связке Must
- **Источник:** SRS REQ-PWR-001/002/004/005/006/007, §6; HARDWARE §1, §5, §8 (P-14, P-15); BOM «Пульт» P-05, P-14, P-15; «Критичные пробелы» P0 строки 2–3; SRS GAP-004; BOM-риски GAP-002/003.
- **Описание:** [Ф] Не выбраны ни аккумулятор, ни система переключения. [В] Выбор ограничен одновременно несколькими Must: питание Pi 4B (5,1 В / 3 А) **и** дисплея (до 6 Вт; BOM P-05 запрещает питать экран от USB-порта Pi); бесшовный переход USB-C ↔ батарея (PWR-004); сигнал низкого заряда для штатного выключения (PWR-005); телеметрия для диагностики (PWR-007); замена без доступа к токоведущим частям (PWR-006); ≥4 ч (PWR-002). Многие готовые UPS-модули для Pi дают один выход ~3 А и/или не отдают телеметрию. Формулировка «Официальный готовый модуль» (PWR-004) не определяет, чей он. Не определено, допускается ли замена батареи на работающем устройстве («сменный» в HARDWARE §1).
- **Оценка энергии [В]:** Pi 4B 3–6 Вт + дисплей ≤6 Вт + вентилятор ~0,5 Вт ≈ 8–13 Вт. 4 ч ≈ 35–55 Вт·ч на выходе, с потерями преобразования ~40–60 Вт·ч номинала; 6 ч (Should) ≈ 60–90 Вт·ч — близко к порогу 100 Вт·ч, важному для транспортировки. Требуется измерение на стенде.
- **Влияние:** блокирует CAD пульта (объём, масса, вентиляция), закупку, PWR-002/004/005, оценку бюджета и массы ≤2 кг. **Не блокирует** ПО: телеметрию питания можно реализовать через абстрактный провайдер с состоянием «недоступно» (PWR-007 это прямо допускает) и эмулятор.
- **Предложение:** Tech Lead выпускает профиль выбора (выходы и токи, бесшовность, интерфейс телеметрии I²C/USB/GPIO, сигнал низкого заряда, сертификация и паспорт изготовителя, условия замены, габариты/масса, температурный диапазон заряда). Специалист по питанию подбирает 2–3 готовых изделия по паспортам; закупка одного для стендового теста до CAD. Замену батареи определить как «только на выключенном устройстве или при подключённом внешнем питании».
- **Закрытие:** выбранное изделие в BOM с SKU, паспортом и ценой; стендовый прогон переключения и разряда; уточнённая формулировка PWR-004 в changelog.
- **Решает:** Владелец (профиль и бюджет) + Питание (подбор).

### AUD-002 · Испытательная база для IP54 и температурных Must не определена
- **Источник:** REQ-R-003 (Must), R-004, R-005 (Must), R-006, P-005, P-009; SRS §6; HARDWARE §6; BOM «Сводка» A17 (испытания вне сметы).
- **Описание:** [Ф] IP54 — Must, подтверждается испытанием готового изделия. [В] Испытание по IEC 60529 для IP5X требует пылевой камеры (тальк, при необходимости разрежение), для IPX4 — качающейся трубы или разбрызгивателя по стандарту; для 0…+40 °C нужна климатическая камера или документированный самодельный термобокс. Ни оборудование, ни исполнитель, ни бюджет испытаний не указаны. Без этого PASS по R-003/R-005 получить нельзя, а самодельная проверка не даёт права заявлять IP54 в строгом смысле.
- **Влияние:** блокирует план приёмки удалённого блока и формулировку доказательства для R-003; влияет на конструкцию, которую нужно проектировать «под методику».
- **Предложение:** вариант A — аккредитованная лаборатория для финального IP54 и климатики (стоимость вне бюджета комплектующих, по коммерческому запросу); вариант B — внутренняя методика по процедурам IEC 60529 и с фото/видео-фиксацией, а в отчёте формулировка «IP54 по внутренней методике, без аккредитации». Рекомендация [В]: B для итераций разработки, A для финального протокола Stable, если позволяет бюджет; иначе B с явной оговоркой в релизе.
- **Закрытие:** утверждённая методика TEST-R-003/005 с оборудованием, исполнителем и формулировкой результата.
- **Решает:** Владелец.

### AUD-003 · Граница корпуса удалённого блока и вводы не определены
- **Источник:** REQ-R-003, R-009, R-010; HARDWARE §1 («внешнее автономное решение»), §6, §7; BOM R-09 (MB16-10G, кабель 6–10 мм), R-10.
- **Описание:** [В] Обжатый разъём RJ45 не проходит через кабельный ввод M16 — нужен либо герметичный проходной RJ45 (IP-rated bulkhead), либо кабель, обжимаемый после ввода. Не определён ввод питания. Не определено, входит ли внешняя АКБ в границу IP54. Не определена конфигурация испытания: с подключёнными кабелями или с заглушками. Нет мембранного клапана выравнивания давления — для герметичного корпуса со сменой температуры это обычный элемент [В].
- **Влияние:** блокирует CAD удалённого блока и методику R-003.
- **Предложение:** граница IP — корпус с Pi, вводы в штатном подключённом состоянии; внешняя АКБ — отдельное готовое изделие со своим паспортом и вне заявления IP54; герметичный RJ45 и ввод питания — покупные IP67-компоненты; добавить мембранный клапан. Решение по границе — владельцу, остальное стандартно.
- **Закрытие:** ICD корпуса (перечень вводов, их тип, конфигурация испытания) в HARDWARE Rev B.
- **Решает:** Владелец (граница IP и место АКБ), HW (компоненты).

### AUD-004 · Тепловая осуществимость пассивного герметичного FDM-корпуса при +40 °C не подтверждена
- **Источник:** REQ-R-005, R-007, R-008; HARDWARE §4, §6.5; BOM R-05, «Критичные пробелы» P1.
- **Описание:** [В] Pi 4B под нагрузкой с кодированием видео выделяет порядка 4–6 Вт. В закрытом корпусе из PETG (плохой проводник тепла; температура размягчения около 70–80 °C) при +40 °C снаружи воздух внутри нагреется заметно выше, а SoC начнёт троттлить около 80 °C. Наклеиваемые радиаторы внутри герметичного корпуса тепло наружу почти не отводят. Скорее всего понадобится тепловой путь к стенке: покупная алюминиевая пластина или радиатор, выходящий наружу.
- **Влияние:** блокирует заморозку CAD удалённого блока; может потребовать покупной металлической детали в «FDM-корпусе» (REQ-R-002) или вентилятора (REQ-R-008 это допускает).
- **Предложение:** до CAD — тепловой макет (упрощённая коробка той же толщины стенок, термологгер, нагрузка stress-ng + видеокодирование, нагрев до +40 °C). Металлический теплоотвод как покупной элемент считать совместимым с REQ-R-002 (корпус остаётся FDM) — требуется подтверждение владельца.
- **Закрытие:** отчёт теплового макета; выбранная тепловая схема в HARDWARE Rev B.
- **Решает:** HW (макет); Владелец — только если понадобится металлическая деталь корпуса или вентилятор.

### AUD-005 · Модель доверия для подписи релизов (одноуровневый ключ в CI без ручного gate)
- **Источник:** REQ-UPD-002/003/007/008; SRS GAP-010; BOM-риски GAP-008 («NOT REVIEWED»).
- **Описание:** [Ф] Корневой открытый ключ закрепляется в образе (UPD-003), смена доверия по сети запрещена, а при компрометации нужна ручная переустановка (UPD-008). Подпись выполняется в едином CI (UPD-007). [В] Если закреплённый корень и ключ подписи CI — один и тот же ключ, то любая компрометация CI (сторонний action, зависимость, токен сопровождающего, push тега) даёт злоумышленнику возможность выпустить «официальный» образ. Тогда ключ придётся менять ручной перепрошивкой каждого устройства. Ключ, закреплённый в первом же выданном образе, впоследствии изменить нельзя.
- **Влияние:** блокирует выпуск любого образа с закреплённым продуктивным ключом и проектирование подсистемы обновлений. GUI и сервисы не блокирует: до решения используются только тестовые ключи.
- **Предложение (рекомендация):** двухуровневая PKI. Офлайн-корень хранится у владельца на аппаратном токене, закреплён в образе и подписывает только промежуточный сертификат. Короткоживущий ключ подписи CI, выпущенный этим корнем, хранится в защищённом GitHub Environment. Подпись выполняется отдельным job только по защищённому тегу и после ручного одобрения владельцем. Подписывается тот же артефакт, который прошёл тесты (проверка хеша). Actions закреплены по SHA, права токенов минимальны, при PR из форков секреты недоступны. Тогда при компрометации CI отзывается промежуточный сертификат, и корень не меняется. Альтернатива — ручная офлайн-подпись владельцем: безопаснее, но меняет смысл REQ-UPD-007.
- **Закрытие:** ADR по PKI, ревизия workflow, настольные учения UPD-008 по новой схеме.
- **Решает:** Владелец.

### AUD-006 · Роль удалённого блока без экрана не определена
- **Источник:** REQ-REL-004 («GUI, сенсорный/физический ввод… отдельно для обоих устройств»), UI-004 («Устройство»), UI-006, PWR-005 (только пульт), PWR-007 («оба»), REC-002, SRS §3 («Локальная диагностика / обновление / восстановление»); HARDWARE §1 (дисплей «не требуется»); BOM: на удалённом блоке нет индикатора и кнопки.
- **Описание:** [Ф] У удалённого блока нет экрана и органов ввода, но Smoke Test (REL-004) требует для обоих устройств проверять GUI и ввод. Не определено, как удалённый блок обновляется, восстанавливается и показывает статус, нужен ли ему индикатор и кнопка, как он выключается при разряде.
- **Влияние:** блокирует архитектуру ПО удалённого блока (агент, канал управления, путь обновления) и CAD (световод, кнопка — дополнительные отверстия в корпусе IP54).
- **Предложение:** удалённый блок работает без экрана. Его диагностику, обновление и экспорт журналов выполняет пульт по лабораторному каналу; образ при этом проверяет подпись на самом удалённом блоке, а не на пульте. Восстановление после отказа загрузки — через сервисный доступ (REQ-R-009) и USB-носитель. Индикация — один RGB-индикатор за герметичным световодом. Внешней кнопки нет: блок включается подачей питания и выключается командой с пульта.
