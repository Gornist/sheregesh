## D1 — Модель доверия для подписи релизов

**Решение владельца.** Вариант A:
- корневой ключ подписи хранится офлайн у владельца;
- для CI используется отдельный ограниченный ключ;
- выпуск официального релиза требует ручного одобрения.

Это изменение ранее утверждённой модели. Ручное подтверждение само по себе не считается достаточной защитой.

**Заменяет:** одноуровневую модель ключей решений №193–198 (корневой открытый ключ в образе = ключ подписи в CI).
**Последствия:**
- REQ-UPD-002/003/007/008 изменены (CHG-004);
- технические меры, модель угроз и процедура восстановления доверия — ADR-0005;
- до проведения церемонии создания корня используются только тестовые ключи;
- образ с продуктивным корнем не выпускается.

## D2 — Испытания IP54 и климатических характеристик

**Решение владельца.** Вариант B для лабораторной версии 1.0:
- испытания выполняются по документированным внутренним методикам с фиксацией условий, оборудования и результатов;
- не называются аккредитованной сертификацией;
- независимая лабораторная проверка остаётся отдельным вариантом;
- все Must сохраняют обязательный критерий PASS.

**Последствия:**
- REQ-R-003/004/005 и P-009 переформулированы (CHG-003);
- методики `docs/tests/methods/IP54-internal.md` и `climate-internal.md` готовятся к этапам H3/H7;
- в каждом протоколе — формулировка «по внутренней методике».

## D3 — Удалённый блок без GUI и органов ввода

**Решение владельца.**
- Удалённый блок работает без собственного GUI и физических органов ввода.
- Настройка, обновления, диагностика и экспорт журналов выполняются через пульт.
- Smoke Test учитывает фактическую конструкцию.
- Индикация состояния — за световодом; обязательной внешней кнопки нет.
- Внешний готовый аккумуляторный блок находится вне границы защиты IP54. Границы испытаний и перечень внешних элементов фиксируются.

**Последствия:**
- REQ-REL-004, UI-004, UI-006, REC-002 изменены (CHG-001);
- тесты TEST-SMOKE-P, -R, -S;
- граница IP и ICD — HARDWARE Rev B §6.2;
- архитектура управления — ADR-0007.

## D4 — Питание пульта

**Решение владельца.** Подтверждено с ограничением:
- бесшовное переключение источников — Must;
- замена аккумулятора — только после выключения или при безопасном питании от внешнего источника, если такая процедура предусмотрена изготовителем;
- бюджет 50 000 ₽ на устройство остаётся Should;
- если Must требует превышения бюджета, представляется сравнительная смета с последствиями; самостоятельно увеличивать бюджет нельзя;
- допускаются только готовые защищённые аккумуляторные решения с документированной совместимостью.

**Последствия:**
- REQ-PWR-004 и PWR-006 изменены (CHG-002);
- профиль выбора и измерения до выбора — `docs/hardware/PRE-CAD-CHECKLIST.md` (раздел P);
- сравнительная смета — при первой котировке, превышающей лимит.

## D5 — Прежняя разработка и чистая история

**Решение владельца.**
- Старая разработка хранится отдельно в приватном архиве; версия 1.0 ведётся с чистой историей.
- Старый код и сторонние материалы автоматически не переносятся.
- До публичного релиза проводится проверка лицензий, конфиденциальных данных и секретов.
- Если обнаруженный SSH-ключ использовался, оценивается необходимость его отзыва и замены. Перемещение или удаление файлов не считается достаточной мерой.

**Последствия:**
- новое Must REQ-REL-011 (CHG-005);
- первичная проверка выполнена — `docs/security/legacy-audit.md`;
- перенос архива в отдельный приватный репозиторий и удаление архивных веток из этого репозитория выполняются только перед открытием репозитория и после подтверждения копии (`docs/security/legacy-audit.md`, раздел 4);
- ветка `v2` уже имеет независимую историю (корневой коммит 88d03e2 без родителей).

## TL-001 — Единый реестр и объективные критерии

- Источник — `docs/requirements/requirements.json`; производные файлы генерирует `tools/reqs/reqgen.py`.
- CI проверяет согласованность, актуальность производных файлов и прослеживаемость изменений относительно baseline Rev A.
- Пороги в критериях PASS предложены Tech Lead (CHG-006), владелец может их изменить. Сюда входит лабораторный диапазон пульта +10…+35 °C для REQ-P-005 (AUD-019).

## TL-002 — Архитектура ПО

ADR-0002…0004, 0006…0008. Решения принимаются с условием: пробы S2 на Pi 4 подтверждают загрузку через tryboot с RAUC и производительность QML с аппаратным декодированием H.264. Если проба не пройдена, соответствующий ADR пересматривается.

## TL-003 — BOM v0.4

- R-06 (TP-Link UE300) исключён из эталона: количество 0, позиция оставлена как альтернатива. Ни одно требование 1.0 не использует второй Ethernet-порт; позиция — наследие «радиоголовы» прежнего проекта. Сумма удалённого блока уменьшилась на 990 ₽.
- Лист «Риски Rev A»: GAP-NNN переименованы в BOM-RISK-NNN, добавлена колонка AUD.
- Лист «Матрица REQ TEST» удалён: второй источник требований недопустим (CHG-008).
- Лист «Стенд и проверки»: добавлено соответствие TEST-ID; T-07 помечен устаревшим.
- Термин «радиоголова» заменён на «удалённый блок».
