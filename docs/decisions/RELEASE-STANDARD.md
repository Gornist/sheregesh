# Стандарт выпуска лабораторного образа (с S5, 2026-10-25)

Цель — регулярное обновление плат без лишних сборок, испытаний и согласований, с проверяемым откатом на каждом шаге.
Инструменты существующие; новые не создаются. Решения владельца — только в двух точках (★).

| # | Шаг | Чем | Готово, когда | Не делать |
|---|---|---|---|---|
| 1 | Код и тесты | ветка `v2`, `pytest` по затронутому | тесты затронутого зелёные | полный прогон локально, если CI его делает |
| 2 | CI | workflow `ci` | зелёный на коммите выпуска | повторный запуск без изменения дерева |
| 3 | Сборка образа | **основной путь** — workflow `image` (нативный arm64, ≈ 8 мин, оба варианта, verify внутри); **запасной** — devbox `os/docker-build.sh` (`SHEREGESH_BUILD_AS_ROOT=1`, ≈ 45 мин, кэш `/work/cache`) | `build-report.json`: commit = выпуск, `dirty: false`, `verify_exit 0` | пересборку неизменённого дерева (`software/`, `os/`, `tools/image/`, `tools/lab-video/` не менялись → образ прежний) |
| 4 | Проверка состава | `verify_image` (в сборке), `tools/image/order_check.sh` (8 прогонов), `owners_check.sh` против эталона CI 57e8fe4 | 0 FAIL, циклов нет, diff владельцев пуст | ручной осмотр того, что проверяет verify_image |
| 5 | Подпись пакета | `shdeploy ota-build --build-report …` на Mac (ключ `~/.ssh/sheregesh-deploy` не покидает Mac) | `.shota` + SHA-256 записаны | — |
| 6 | Файловое испытание | `tools/deploy/ota-check/run.py` на devbox: установка агентом текущего образа платы и агентом кандидата, откат | install/rollback без FAIL | повтор, если пакет и агенты те же |
| ★ | **Утверждение владельцем** | один запрос: SHA пакета, коммит, итоги 3–6, план и STOP | «утверждаю OTA <плата> пакетом <SHA>» | промежуточные согласования |
| 7 | Аппаратное обновление | `shdeploy ota-install --sha256` → `ota-tryboot` → проверки на пробном слоте → `ota-confirm`; одна плата за раз; slot_guard «до/после» | COMMITTED на новом слоте | подтверждать при любом STOP; принудительное выключение питания |
| 8 | Короткая приёмка | сценарий изменённого (для S5 — `tools/probe/s5_pi2_accept.py`), 5–10 мин | PASS по изменённым функциям | повтор неизменённых подсистем (30-мин soak, E2E-01…15, кабели, полная OTA-регрессия) без конкретной причины |

**Код без системных изменений** (`software/` под launcher) — шаги 3–7 не нужны: DEV deploy (`shdeploy deploy`), откат
`shdeploy rollback`.

**STOP (общие):** нет SSH на пробном слоте > 10 мин; failed-юниты; `sheregesh-health` не PASS; адрес DHCP сменился;
slot_guard показывает неожиданные отличия; любое сомнение → не подтверждать, `ota-abort` / цикл питания → прежний слот.

**Параллельно, не ожидая оборудования:** программные задачи (код, CI, сборка, файловые испытания) не ждут прихода
устройств и решений по другим платам.
