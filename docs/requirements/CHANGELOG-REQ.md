# Журнал изменений требований

_Сгенерировано из раздела `changes` реестра требований. Не редактировать вручную._

Baseline: `docs/baseline/rev-a/SHEREGESH-REQUIREMENTS.json` (Rev A). Текущая редакция: B от 2026-10-22.

## CHG-001 — Удалённый блок без GUI и органов ввода

- **Дата:** 2026-10-22; **основание:** D3
- **Затронутые REQ:** REQ-REL-004, REQ-UI-004, REQ-UI-006, REQ-REC-002
- **Затронутые TEST:** TEST-SMOKE-P, TEST-SMOKE-R, TEST-SMOKE-S

Smoke Test, индикация, кнопка питания и экспорт данных удалённого блока приведены к его фактической конструкции: управление через пульт, индикатор за световодом, без обязательной внешней кнопки.

## CHG-002 — Бесшовное переключение питания; правила замены аккумулятора

- **Дата:** 2026-10-22; **основание:** D4
- **Затронутые REQ:** REQ-PWR-004, REQ-PWR-006
- **Затронутые TEST:** —

Бесшовное переключение подтверждено как Must с готовым модулем, у которого документирована совместимость. Замена аккумулятора — только на выключенном устройстве или при внешнем питании, если это предусмотрено изготовителем. Бюджет остаётся Should; повышать его самостоятельно запрещено.

## CHG-003 — IP и климат — по внутренним методикам

- **Дата:** 2026-10-22; **основание:** D2
- **Затронутые REQ:** REQ-R-003, REQ-R-004, REQ-R-005, REQ-P-009
- **Затронутые TEST:** —

IP54/IP65 и температурные испытания выполняются по документированным внутренним методикам без заявления об аккредитованной сертификации; критерий PASS сохраняется; граница IP — корпус блока, внешний аккумулятор вне её.

## CHG-004 — Двухуровневая модель доверия для подписи

- **Дата:** 2026-10-22; **основание:** D1
- **Затронутые REQ:** REQ-UPD-002, REQ-UPD-003, REQ-UPD-007, REQ-UPD-008
- **Затронутые TEST:** —

Корень хранится офлайн у владельца; CI использует ограниченный ключ выпуска; официальный релиз требует ручного одобрения при обязательных технических мерах; процедура компрометации для двух уровней. Заменяет одноуровневую модель решений №193–198 (ADR-0005).

## CHG-005 — Проверка перед публикацией

- **Дата:** 2026-10-22; **основание:** D5
- **Затронутые REQ:** REQ-REL-011
- **Затронутые TEST:** TEST-REL-011

Новое Must REQ-REL-011: перед публикацией проверяются лицензии, конфиденциальные данные и секреты по всей истории; найденный секрет отзывается и заменяется; история прежней разработки не публикуется.

## CHG-006 — Объективные критерии PASS для всех требований

- **Дата:** 2026-10-22; **основание:** TL-001
- **Затронутые REQ:** *
- **Затронутые TEST:** *

Для каждого требования критерий Rev A заменён перечнем объективных условий PASS, добавлены метод, оборудование и доказательство. Смысл и приоритет требований не изменены. Числовые пороги (время, количество повторов, температуры, лабораторный диапазон пульта +10…+35 °C) предложены Tech Lead и действуют, пока владелец не примет иного решения.

## CHG-012 — Явное правило совместимости протокола

- **Дата:** 2026-10-23; **основание:** TL-004
- **Затронутые REQ:** REQ-SW-003, REQ-SYS-008
- **Затронутые TEST:** TEST-SW-003, TEST-SYS-008

Rev A (REQ-SW-003) требовала проверку MAJOR.MINOR, но правила не задавала. Правило «одинаковый MAJOR — совместимо» было введено ADR-0007 и критериями CHG-006 без отдельной записи — это исправлено здесь. Новое правило строже: дополнительно MINOR второй стороны не ниже минимума из матрицы, отклонённые версии ПО и недопустимые HW-версии; сессия работает на MAJOR.min(MINOR); сообщения новее версии сессии не исполняются. Матрица перенесена в software/sheregesh/compat-matrix.yaml, чтобы устанавливаться вместе с ПО.
