# Хост сборки на Raspberry Pi 5

## Железо

| Что | Требование |
|---|---|
| Плата | Raspberry Pi 5 (проверено на Rev 1.1, **2 ГБ ОЗУ**; 4–16 ГБ — тем лучше) |
| Накопитель | NVMe SSD на M.2 HAT (проверено: Waveshare M.2 HAT C + SK hynix BC711 256 ГБ). Не меньше 64 ГБ, лучше 256 ГБ |
| Питание | блок 5 В / 5 А (27 Вт) с кабелем USB-C; порт USB-C у Pi 5 — **только питание**, данных по нему нет |
| Охлаждение | радиатор с вентилятором (под нагрузкой сборки плата греется до 50–55 °C) |
| Сеть | Ethernet на роутер/коммутатор; адрес по DHCP, лучше закрепить в роутере |
| Прочее | microSD (одна), картридер на компьютере для записи |

Диск бывает не новым: проверьте износ (`nvme smart-log`, поле `percentage_used`) до начала эксплуатации.

## Образ хоста

Образ собирается самим сервисом (ему нужен хотя бы один хост сборки, например x86-64 с эмуляцией) и содержит всё нужное:

- Docker (`docker.io`, `docker-cli`), git, rsync, zstd, python3, `iproute2`, `nvme-cli`, `smartmontools`, `tmux`;
- вход по SSH **только по ключу** (пользователь `shbuild`, root тоже), пароли отключены, `sudo` без пароля для `shbuild`;
- первая загрузка: корень растёт на весь носитель (`shbuild-growroot`), создаётся файл подкачки 8 ГиБ (`shbuild-swap`);
- zram-подкачка, аппаратный сторож systemd, журнал на диске, mDNS (`pi5.local`), PCIe x1 для NVMe (`dtparam=pciex1`);
- обновление прошивки EEPROM отключено (`rpi-eeprom-update` замаскирован): только вручную.

Особенность: ядро Pi 5 использует страницы по 16 КиБ, поэтому ext4 в образе создаётся с блоком 4 КиБ — такой корень
монтируется и ядром Pi 5, и ядром Debian (4 КиБ), которое используется в загрузочном тесте.

```sh
python3 tools/build/shbuild.py submit --config <имя>-buildhost-pi5
python3 tools/build/shbuild.py wait <id> && python3 tools/build/shbuild.py fetch <id>
```

## Запись на NVMe

Вариант А (проще всего): NVMe в USB-корпусе на компьютере, затем в HAT. Найдите диск (`diskutil list` / `lsblk`) —
**внешний, нужного размера**:

```sh
zstd -dc <имя-образа>.img.zst | sudo dd of=/dev/rdiskN bs=4m      # macOS; на Linux: of=/dev/sdX bs=4M conv=fsync
```

Вариант Б: загрузить плату с любой карты Raspberry Pi OS (версии, где есть поддержка Pi 5: 2023-10 и новее), передать
`.img.zst` по сети и записать `zstd -dc … | sudo dd of=/dev/nvme0n1 bs=4M conv=fsync`. После записи сверьте хеш
записанного с образом и проверьте наличие вашего ключа в `/home/shbuild/.ssh/authorized_keys` на новом разделе.

## Порядок загрузки (EEPROM)

На актуальной прошивке порядок по умолчанию `BOOT_ORDER=0xf461`: SD → NVMe → USB. **Вставленная карта загрузится вместо NVMe**
(удобно для спасения), без карты плата идёт с NVMe. Проверка: `vcgencmd bootloader_version`, `rpi-eeprom-update`.

## Первая загрузка и проверка

Через 2–3 минуты плата появляется в сети; `ssh shbuild@pi5.local`.

```sh
df -h /                    # корень вырос до размера NVMe
free -m; cat /proc/swaps   # ОЗУ, zram и /var/swapfile (8 ГиБ)
systemctl is-active docker
ls -l /dev/kvm             # нужен загрузочному тесту (KVM)
sudo nvme smart-log /dev/nvme0 | grep -E 'temperature|percentage_used|critical'
sudo lspci -vv -s 0001:01:00.0 | grep -i lnksta     # Speed 5GT/s (Gen 2), Width x1
vcgencmd measure_temp
```

Затем установите сервис с компьютера ([README.md](README.md)) и запустите первое задание.

## Если плата не загружается

Слот microSD и NVMe проверяются независимо; записывайте конфигурацию на карту **до** первой загрузки (после неё
cloud-init не применит правок повторно).

| Симптом | Что делать |
|---|---|
| Горят только красные светодиоды, зелёный не мигает | образ карты без поддержки Pi 5 (старше 2023-10): перезаписать свежим Raspberry Pi OS (в `/boot` должны быть `kernel_2712.img` и `bcm2712-rpi-5-b.dtb`) |
| Зелёный горит ровно, в сети плат нет | проверить кабель (светодиоды у Ethernet-порта), блок питания, карту; включить без карты и NVMe (HAT снять) и сравнить; нужен UART или монитор micro-HDMI |
| Загрузчик не стартует | карта восстановления: FAT32 с `recovery.bin`, `pieeprom.upd`, `pieeprom.sig` для Pi 5 из [rpi-eeprom](https://github.com/raspberrypi/rpi-eeprom) (`firmware-2712/default`). После успеха `recovery.bin` переименован в `recovery.000` |
| Порт Ethernet не поднимается | адаптер USB-Ethernet у компьютера мог отсоединиться: проверить, что интерфейс есть и в состоянии `active` |

Пароль root и пользователей нигде не хранится; для входа нужен только закрытый ключ, парный открытому, вшитому при сборке.

## Опционально: PCIe Gen 3

`dtparam=pciex1_gen=3` в `/boot/firmware/config.txt` (раздел `[pi5]`) удваивает пропускную способность NVMe, но вне
спецификации. Меняйте только когда можно физически добраться до платы: при неудаче загрузка со спасательной карты и
правка файла на NVMe возвращают прежнее состояние.
