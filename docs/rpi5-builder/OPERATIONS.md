# Эксплуатация: установка, выключатели, замеры, откат

## Установка и обновление

С компьютера, на каждый хост отдельно:

```sh
export SHBUILD_HOST=shbuild@pi5.local SHBUILD_BULK_HOST=shbuild@pi5.local    # хост команд / хост больших передач
python3 tools/build/shbuild.py install            # код, каталоги, набор машины загрузочного теста, ключи
```

`install` создаёт `~/shbuild/{bin,jobs,artifacts,inbox,keys,baseline,vm}`, копирует код и собирает набор для
загрузочного теста (ядро Debian, модули, busybox, контейнер `shbuild-qemu`). Открытые ключи, которые сборка вшивает в
образ, берутся с компьютера; закрытые ключи на хост не копируются. Переменные `SHBUILD_HOST` и `SHBUILD_BULK_HOST`
задавайте всегда: значения по умолчанию в коде — имена чужой машины.
После любого изменения кода сервиса — `install` на все хосты; пока задание выполняется, не ставьте.

## Выключатели оптимизаций

Файл `~/shbuild/host.conf` на хосте: строки `имя=значение`, `#` — комментарий. Нет файла или строки — значение по
умолчанию. Действует со следующего задания, переустановка не нужна; действовавшие значения пишутся в `state.json`.

| Выключатель (по умолчанию) | Что делает | Откат |
|---|---|---|
| `parallel_tests` (1) | этап `tests` одновременно со `build` | `parallel_tests=0` |
| `parallel_gates` (1) | `owners_check` одновременно с `order_check` | `parallel_gates=0` |
| `parallel_boot` (**0**) | `gates` одновременно с `boot` (на Pi 5 даёт ENOMEM у KVM) | включить: `parallel_boot=1` |
| `zstd_level` (3) | уровень сжатия итогового образа | `zstd_level=10` (меньше файл, +80 с на Pi 5) |

```sh
ssh shbuild@pi5.local 'echo parallel_tests=0 >> ~/shbuild/host.conf'      # откат одной строкой
```

Откат кода: `git revert <коммит>`, затем `install` на хосты. Сохраняйте метку на последнюю проверенную версию перед
ускорениями.

## Замеры (образ ≈ 7 ГБ, A/B-разметка, ≈ 600 пакетов, `PASSED`)

| Конфигурация | tests | build | gates | boot | Всего |
|---|---|---|---|---|---|
| Pi 5, программная эмуляция загрузки (TCG), всё по очереди | 24 с | 686 с | 65 с | 675 с | ≈ 25 мин |
| Pi 5, KVM, образ один раз, пауза по условию | 24 с | 527 с | 68 с | 128 с | 748 с |
| + `zstd -3`, `owners ‖ order` | 24 с | 436 с | 56 с | 128 с | 644 с |
| + `tests ‖ build` (**по умолчанию**) | 25 с | 433 с | 55 с | 128 с | **617 с** |

Распределение `build` (Pi 5, ≈ 430 с): подготовка контейнера ≈ 30 с; установка пакетов в chroot ≈ 145 с (скачивание
≈ 200 МБ ≈ 40 с); SBOM ≈ 19 с; сборка разметки ≈ 107 с; упаковка rpi-image-gen ≈ 55 с; проверка структуры ≈ 25 с;
сжатие ≈ 38 с. Загрузочный тест (KVM) ≈ 30 с на сценарий; распаковка образа — 13 с один раз.

### Пробовали и отвергли

- **Отключить сжатие в хуке rpi-image-gen** (`deploy.compression: none`): само копирование быстрее на 15 с, но следующий хук
  хеширует 7 ГБ несжатого образа (+14 с). Итог 0, откачено.
- **Два сценария загрузки одновременно**: на 2 ГБ ОЗУ `KVM_CREATE_VM: Cannot allocate memory`, выигрыш ≈ 25 с. Откачено.
- **`gates ‖ boot`**: выигрыш ≈ 20 с, но та же ошибка KVM бывает даже с одной машиной. Оставлено выключателем, по умолчанию выкл.
- **Кэш пакетов (apt-cacher-ng)**: ≈ 35 с, но новый постоянный сервис и https-зеркала. Не делалось.

Не пробовали: PCIe Gen 3 (риск, см. [HOST-SETUP.md](HOST-SETUP.md)); ускорение проверки структуры чтением разделов
`debugfs` по смещению без копий (≈ 10–20 с).

Принцип: прежде чем принять ускорение, повторите прогон минимум дважды — один зелёный прогон не доказывает, что
конкурирующие процессы на 2 ГБ ОЗУ не дают редкого сбоя.

## Мониторинг хоста

```sh
python3 tools/build/shbuild.py status                  # очередь и последние задания
ssh shbuild@pi5.local 'df -h /; free -m; cat /proc/swaps; vcgencmd measure_temp'
ssh shbuild@pi5.local 'sudo nvme smart-log /dev/nvme0 | grep -E "percentage_used|critical|temperature"'
ssh shbuild@pi5.local 'tail -50 ~/shbuild/worker.log'
```

Износ NVMe (`percentage_used`) — главный ресурс хоста: сборка пишет десятки ГБ за задание. Диск 256 ГБ даёт сотни
сборок; следите за значением и держите свободным ≥ 50 ГБ.

## Частые причины провала

| Симптом | Причина / что делать |
|---|---|
| `preflight`: «память … ОЗУ + подкачка» | на хосте нет подкачки на диске (`cat /proc/swaps`); на Pi 5 её создаёт `shbuild-swap` после расширения корня |
| `tests`: «нет debugfs» | исполнитель запущен без `/usr/sbin` в `PATH`; переустановить сервис (в `worker_env` добавлено) |
| `gates`: владельцы отличаются от эталона | состав владельцев файлов изменился: разобраться, эталон менять осознанно, отдельным коммитом |
| `boot`: «нет журнала консоли машины» | машина не стартовала (KVM/ОЗУ); `logs <id> boot`, ручной запуск `SHBOOT_KEEP=1 bash boot_check.sh …` |
| `boot`: `KVM_CREATE_VM … Cannot allocate memory` | нехватка/фрагментация памяти при одновременной нагрузке; выключить `parallel_boot`, не гонять гейты рядом |
| `boot`: упавший юнит | дефект образа; юнит можно разрешить в `ALLOW_FAILED` только с причиной |
| `build`: `dirty: true` | собрано не из коммита; сервис собирает `git worktree`, ручные обходы запрещены |
| задание ждёт | идёт другое, исполнитель один: `status` |
| хост не отвечает после перезагрузки | задание в этот момент оборвётся (`ERROR`); когда хост поднялся, поставить задание заново |

## Безопасность

- Вход на хост — только по ключу (root тоже); закрытые ключи остаются на вашем компьютере.
- Сервис не раздаёт сеть наружу, использует исходящие загрузки пакетов (Debian, Raspberry Pi) и Docker Hub.
- Не запускайте сборки непроверенных коммитов чужих авторов на хосте, который имеет доступ к вашим ключам: сборка идёт в
  привилегированном контейнере.
- Артефакты на хосте не подписаны; подписывайте выпуски на отдельной машине, ключ подписи на хост не кладите.
