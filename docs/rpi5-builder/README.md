# shbuild: сборка образов Raspberry Pi на Raspberry Pi 5

`shbuild` — небольшой сервис сборки образов Raspberry Pi OS на базе [rpi-image-gen](https://github.com/raspberrypi/rpi-image-gen).
Работает на **Raspberry Pi 5 с NVMe** (нативный arm64, без эмуляции) или на обычной x86-64 машине с `qemu-user`. Берёт
коммит, ставит его в очередь и по одному заданию проводит: тесты → сборка образа → проверки → загрузочный тест
образа в QEMU (на Pi 5 под KVM). Образ получает статус `PASSED` только если прошли **все** этапы.

Для образа в ≈ 7 ГБ с ≈ 600 пакетов на Pi 5 весь конвейер занимает около **10 минут** (на x86-64 с эмуляцией ≈ 37 минут).

## Зачем

- **Воспроизводимо и без ручных шагов.** Сборка идёт из коммита (`git worktree`), а не из рабочей папки;
  `SOURCE_DATE_EPOCH` — время коммита. Одна команда вместо цепочки «bundle, scp, переменные, rsync обратно, гейты по одному».
- **Дефекты ловятся до железа.** Многие проблемы образа видны только при загрузке (юниты, имена, DHCP, сеть), поэтому
  образ загружается целиком в QEMU с настоящим systemd, а результат проверяется по набору условий.
- **Явные итоги.** `PASSED`, `FAILED` (дефект кода или образа), `ERROR` (среда), `CANCELLED`, `TIMEOUT`. Тихих обрывов нет.
- **Образ на железо — только проверенный.** Отчёт `shbuild-report.json` создаётся лишь при `PASSED`; инструменты записи
  и раскатки могут требовать его наличие.

## Как это устроено

```
 ваш компьютер              хост сборки (Pi 5 + NVMe или x86-64)
 ┌────────────┐  ssh   ┌──────────────────────────────────────────────┐
 │ shbuild.py │───────▶│ очередь (один исполнитель) ─▶ задание        │
 │ submit/wait│  git   │  preflight ▸ checkout ▸ tests ▸ build        │
 │ fetch      │ bundle │            ▸ gates ▸ boot (QEMU/KVM)        │
 └────────────┘◀───────│ artifacts/<коммит>/ …img.zst, отчёты        │
     образы              └──────────────────────────────────────────────┘
```

Компьютер — любой с Python 3 и SSH, ничего не собирает. Хост сборки — отдельная машина с Docker.

## Быстрый старт

1. **Подготовьте хост.** Pi 5 с NVMe: [HOST-SETUP.md](HOST-SETUP.md) (собрать образ хоста, записать на NVMe, первая
   загрузка). Либо любая Linux-машина с Docker, `qemu-user-static` и ≥ 40 ГБ диска.
2. **Установите сервис** (код, каталоги, набор машины загрузочного теста, ваши открытые ключи):

   ```sh
   export SHBUILD_HOST=shbuild@pi5.local SHBUILD_BULK_HOST=shbuild@pi5.local
   python3 tools/build/shbuild.py install
   ```

3. **Закоммитьте изменение и отправьте задание:**

   ```sh
   python3 tools/build/shbuild.py submit                 # HEAD; печатает id задания
   python3 tools/build/shbuild.py wait <id>              # одна строка итога; код 0 — PASSED
   python3 tools/build/shbuild.py fetch <id>             # забрать артефакты PASSED
   ```

Остальные команды: `status [id]`, `logs <id> [этап]`, `cancel <id>`. Подробности — [PIPELINE.md](PIPELINE.md),
эксплуатация, выключатели, замеры и откат — [OPERATIONS.md](OPERATIONS.md).

## Что ожидает сервис от проекта

Сервис не «знает» ваш образ, он вызывает ваши скрипты. Проекту нужно:

| Что | Роль |
|---|---|
| `os/rpi-image-gen.ref` | коммит rpi-image-gen, под который собирается образ |
| `os/docker-build.sh` | запускает сборку в привилегированном контейнере arm64; получает `SHBUILD_JOB` (без него отказывает) |
| `os/build.sh` | внутри контейнера собирает образ и кладёт результат: `*.img.zst`, `SHA256SUMS`, `build-report.json`, `verify.json`, SBOM |
| `os/config/<имя>.yaml` | конфигурация rpi-image-gen образа (слои, разметка, имя) |
| проверки структуры образа (`verify_*.py`) | по желанию: разметка, файлы, юниты; код возврата ≠ 0 — провал |
| `owners_check.sh`, `order_check.sh` | по желанию: владельцы файлов против эталона, отсутствие циклов упорядочения systemd |
| `tests/tools` | модульные тесты (`unittest`), этап `tests` |

В комплекте есть рецепт образа самого хоста сборки (`<имя>-buildhost-pi5`) — он собирается тем же конвейером.

## Ограничения

- Один исполнитель на хост: задания идут по очереди.
- Загрузочный тест — QEMU `virt` с ядром Debian: он проверяет systemd, сеть, службы и их конфигурацию, но **не** прошивку,
  ядро Pi, загрузчик, GPIO, дисплей и не заменяет испытание на реальной плате.
- Рассчитан на образы rpi-image-gen. Другие сборщики образов потребуют своих `docker-build.sh`/`build.sh`.

Лицензия — в корне репозитория.
