# Секреты в «Шерегеш» 1.0

Перечень нужен для REQ-SW-005 и REQ-REL-011: секреты не попадают в журналы, экспорты, файлы состояния и релизные
вложения. Редакция 2026-10-31: после D8 (CHG-016) корневой ключ подписи и ключ выпуска CI требованиями не являются —
подпись выпусков и OTA делает ключ владельца.

| Класс | Где живёт | Где не должен оказаться |
|---|---|---|
| Ключ подписи выпусков DEV и пакетов OTA | Только на машине владельца (`~/.ssh/sheregesh-deploy`, подпись `ssh-keygen -Y sign` локально); на платах — открытый ключ в `allowed_signers` образа | Репозиторий, платы, CI, журналы |
| Ключ устройства канала управления (mTLS) | Раздел данных платы: `~/.local/share/sheregesh/link/device.key` пользователя `sheregesh-ui`, 0600 | Журналы, экспорт журналов, файлы состояния, образы |
| Ключи SRTP видеосеанса | Только в памяти служб `sheregesh-video-tx/rx` от `start` до `stop`; передаются в `video-key` по каналу mTLS | Журналы (только `key_b64: ***`), `state.json`, диск |
| Ключи хоста SSH | `/etc/ssh/ssh_host_*_key` платы | Журналы, экспорт, образы |
| Вход root (только DEV-образ) | По ключу владельца; паролей нет | — |

**Проверка на платах:** `tools/probe/check_secrets_in_logs.py` — фрагменты настоящих ключей (на плате, наружу только
счётчики) ищутся в journald всех загрузок, `/var/log`, `/run/sheregesh*`, `/tmp` и экспортах; контроль — канарейка
`SHRG-CANARY-SW005-<случайная>` в journald и `/tmp` должна найтись.

**Канареечные секреты в автотестах:** строки вида `SHRG-CANARY-<класс>-<случайный>`; тесты размещают их там, где
живут секреты (с тестовыми ключами), и проверяют их отсутствие в журналах и экспорте. Продуктивные секреты в тестах не
используются.

Паролей и ключей по умолчанию в образах 1.0 нет.
