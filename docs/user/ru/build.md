# Сборка

Как с нуля собрать образ «Шерегеша» и запустить пару плат: пульт и удалённый блок на Raspberry Pi 4B.
Корпуса, питание и дисплей пока не выбраны: сборка железа будет описана после выбора оборудования.
Термины — в разделе «Вопросы и термины».

## Что нужно

- **Платы:** две Raspberry Pi 4B, две карты microSD от 8 ГБ, кабель Ethernet между платами или общая сеть с DHCP.
- **Видео для блока:** HDMI-захват USB (проверен MacroSilicon MS2130), камера UVC, аналоговый вход или поток RTSP.
  Без источника видео обновление системы не подтверждается — см. «Обслуживание».
- **Машина разработчика:** Git, Python 3.11+, OpenSSH. Запись карты скриптом — macOS; на Linux — вручную (ниже).
- **Машина сборки:** Linux x86-64 с Docker и qemu-user-static (сборка для aarch64), от 40 ГБ свободного диска
  и 6 ГБ памяти, вход по SSH по ключу. Это может быть та же машина, что и машина разработчика.

## Без железа: эмуляторы

```sh
tools/dev/sheregesh-emu --demo          # пульт и удалённый блок отдельными процессами, сценарий неисправностей
tools/dev/sheregesh-emu --test          # все автотесты без дисплея
```

## Ключи

Нужны два ключа SSH. Закрытые ключи остаются на машине разработчика, в образ попадают только открытые.

```sh
ssh-keygen -t ed25519                                               # вход на платы (если ключа ещё нет)
ssh-keygen -t ed25519 -f ~/.ssh/sheregesh-deploy -C sheregesh-deploy  # подпись выпусков и обновлений
```

Ключ CA для сертификатов плат создаётся позже (`labpki.py init`) в `~/.sheregesh-lab-ca`. Сохраните копию этого
каталога: без него выдать сертификат новой плате можно только с новым CA и повторным сопряжением обеих плат.

## Образ системы

Образы собирает только сервис shbuild на машине сборки: каждый образ проходит тесты, проверку состава и загрузочный
тест в эмуляторе, в том числе первую загрузку без сети.

```sh
export SHBUILD_HOST=сборка SHBUILD_BULK_HOST=сборка   # имя машины сборки в ~/.ssh/config (по умолчанию devbox)
python3 tools/build/shbuild.py install          # один раз: сервис, сборщик и ваши открытые ключи
python3 tools/build/shbuild.py submit           # отправить текущий коммит, будет напечатан номер задания
python3 tools/build/shbuild.py wait ЗАДАНИЕ     # дождаться итога: PASSED или причина отказа
python3 tools/build/shbuild.py fetch ЗАДАНИЕ КАТАЛОГ
```

`install` берёт открытые ключи из `~/.ssh/id_ed25519.pub` и `~/.ssh/sheregesh-deploy.pub` (другие — `--dev-key`,
`--deploy-key`). Устанавливать можно только образ с итогом PASSED: инструменты записи и обновления отвергают другие.
Собирается вариант для лаборатории с входом по SSH (DEV-образ) — другие варианты пока не поддерживаются.

## Запись карты

На macOS:

```sh
python3 tools/image/flash_sd.py КАТАЛОГ/sheregesh-lab-dev-pi4.img.zst              # показать подходящие карты
python3 tools/image/flash_sd.py КАТАЛОГ/sheregesh-lab-dev-pi4.img.zst --disk diskN # записать и сверить
```

Скрипт пишет только на внешний диск и сверяет записанное с контрольной суммой. Карту с уже установленной системой
он без явного согласия не перезапишет.

На Linux распакуйте образ и сверьте его с отчётом сборки, затем запишите Raspberry Pi Imager («Use custom»)
или `dd`, проверив имя устройства карты:

```sh
zstd -d КАТАЛОГ/sheregesh-lab-dev-pi4.img.zst -o sheregesh.img
sha256sum sheregesh.img            # должно совпасть с image_sha256 в КАТАЛОГ/build-report.json
```

## Первая настройка пары

1. Запишите образ на обе карты, вставьте их и включите платы. До сопряжения у обеих одно имя `sheregesh-dev`:
   включайте платы по одной и находите адрес каждой в списке DHCP роутера.
2. Проверьте вход: `ssh sheregesh-ui@АДРЕС`. Новая плата принимается без правки `known_hosts`. Если карту
   перезаписали, а адрес остался прежним, SSH сообщит о смене ключа хоста: `ssh-keygen -R АДРЕС`.
3. Создайте CA и сопрягите платы:

   ```sh
   python3 tools/lab-pki/labpki.py init
   python3 tools/lab-pki/labpki.py pair --console АДРЕС_ПУЛЬТА --remote АДРЕС_БЛОКА
   ```

   `pair` сначала проверяет обе платы, затем выдаёт сертификаты, связывает платы, записывает их в реестр плат
   (`~/.config/sheregesh/boards.json`, имена pi1 и pi2) и перезапускает службы. Ключ устройства создаётся на плате
   и её не покидает. После перезагрузки платы называются по роли: `pi1` — пульт, `pi2` — блок.
4. Пульт сам находит блок и устанавливает защищённый канал (TLS 1.3 с взаимной аутентификацией). Проверка — раздел
   «Диагностика» пульта, `sheregesh-health` на плате или с машины разработчика:

   ```sh
   python3 tools/stand/boards.py list
   python3 tools/deploy/shdeploy.py status pi1
   python3 tools/probe/smoke.py --out КАТАЛОГ   # автоматические пункты проверки пары
   ```

Заменить одну плату (новая карта, новый блок) — тот же `pair` с текущими адресами обеих плат. Свои имена плат —
`--names пульт,блок`; добавить плату в реестр без сопряжения — `python3 tools/stand/boards.py add ИМЯ --host АДРЕС
--role console|remote`.
