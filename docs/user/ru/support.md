# Обслуживание

Повседневная работа с парой плат: состояние, журналы, обновления, сертификаты.

## Состояние

- **Пульт, строка состояния:** управление, связь с блоком и её задержка, видео, устройство ввода, модуль, часы.
  Активная авария показывается полосой поверх видео; касание открывает «Диагностику».
- **Раздел «Диагностика»:** связь, видео, службы пульта и блока, события с рекомендациями.
- **Раздел «Система»:** версия ПО, состояние обновления, образ системы, режим разработчика.
- **На плате:** `sheregesh-health` проверяет службы, хранилище, питание и температуру. `sheregesh-info` показывает
  паспорт: роль, версию ПО, сборку образа, версию железа и серийный номер.
- **С машины разработчика:** `python3 tools/deploy/shdeploy.py status pi1`.

Температура в диагностике — датчик SoC платы. Питание показывается как «нет данных»: модуля питания на стенде нет.

## Журналы и резервная копия

- **«Диагностика» → «Выгрузить журнал»** сохраняет журнал пульта с контрольной суммой; секреты в нём заменены
  на `[REDACTED]`. Там же **«Выгрузить журнал блока»** — журнал служб удалённого блока за текущую загрузку.
- **«Настройки» → «Резервная копия на USB»** сохраняет конфигурацию. Ключи и сертификаты канала в копию не входят.

Внешний накопитель пока не монтируется: «USB» — это каталог `/var/lib/sheregesh/usb` на пульте. Забрать файлы
можно по SSH:

```sh
scp 'sheregesh-ui@АДРЕС_ПУЛЬТА:/var/lib/sheregesh/usb/*' .
```

Журналы служб на плате: `journalctl -u sheregesh-console`, `-u sheregesh-remote-net`, `-u sheregesh-video-tx`.
Команды обслуживания блока с пульта (на плате пульта, начиная с нового образа): `sheregesh-remotectl log-export`,
`sheregesh-remotectl shutdown --confirm`.

## Выключение удалённого блока

У блока нет кнопки питания. Он выключается с пульта: «Система» → «Выключить удалённый блок…» и подтверждение
(по умолчанию выбрана «Отмена»). Блок завершает службы и выключается; на пульте поверх видео — «Блок выключен».
Чтобы включить блок снова, выключите и включите его питание.

## Настройки

Каждое применение создаёт новую ревизию конфигурации. Службы проверяют её, и при ошибке автоматически
возвращается прежняя ревизия. Действия, меняющие устройство, выполняются только после отдельного подтверждения.
Поля ввода заполняются экранной клавиатурой — она появляется при касании поля.

## Обновление приложения

Код приложения без системных изменений обновляется подписанным выпуском, без перезаписи карты:

```sh
python3 tools/deploy/shdeploy.py deploy pi1        # затем pi2
python3 tools/deploy/shdeploy.py rollback pi1      # вернуть предыдущий выпуск
python3 tools/deploy/shdeploy.py factory pi1       # вернуться к коду образа
```

Выпуск, после которого служба падает, откатывается сам.

## Обновление системы (OTA A/B)

Новый образ записывается в неактивный слот, рабочий слот при этом не меняется. Пакет обновления собирается
из образа с итогом PASSED, затем одна команда проводит плату через все шаги:

```sh
python3 tools/deploy/shdeploy.py ota-build --image ОБРАЗ --build-report build-report.json --out ПАКЕТ
python3 tools/deploy/shdeploy.py ota-update pi1 --payload ПАКЕТ/*.shota --sha256 SHA
```

`ota-update` устанавливает пакет, разрешает переключение слотов, делает пробную загрузку, ждёт плату, проверяет
её и подтверждает. Если проверки не прошли, плата возвращается в рабочий слот. Если плата не вернулась после
пробной загрузки, выключите и включите питание: загрузится рабочий слот. Отдельные шаги — `ota-install`,
`ota-enable`, `ota-tryboot`, `ota-confirm`, `ota-abort`, `ota-disable`, `ota-status`.

Обновляйте платы по одной, пульт первым. При подтверждении проверяются службы, связь и видео. На стенде без
источника видео проверку видео можно выключить (root на плате):

```sh
echo '{"require_video": false}' > /persistent/sheregesh-ota/settings.json
```

## Сертификаты

Сертификаты плат действуют 365 дней, CA — 730 дней (`labpki.py status --host АДРЕС`). Продление — повторное
сопряжение: `labpki.py pair` с текущими адресами плат. Когда истекает CA, создайте новый (`labpki.py init` в
пустом каталоге `~/.sheregesh-lab-ca`) и сопрягите платы заново. Храните копию `~/.sheregesh-lab-ca` вне машины
разработчика.
